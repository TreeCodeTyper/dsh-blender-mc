> 面向接手这个插件的人 / agent。**先看第 2 节**：三棵源码树是这里最容易出事的地方，

## 1. 这个项目是什么

把 Minecraft Java 存档变成 **Blender 封面图 / 动画 / 分镜成片 / 可编辑背景地图**，并尽量自动：

```
存档 .mca ──scan──▶ 机位(积分图平地+距离变换+RANSAC+DDA+Pareto)
   │
   ├─export──▶ 世界.obj ──build_cover──▶ Blender 渲染 ──vision_check──▶ 不合格改参数重渲
   │
   ├─import_map──▶ 背景_世界.blend（MAP/LIGHTS/CAMERA）
   │
   └─anim / film──▶ 预设动画 / 提示词分镜 ──▶ MP4

本机存档目录 ──local──▶ 地图库（savePath 指向原目录，不复制 .mca）
```

对外是 DSH 插件（`lib/index.js` 注册 13 个 `mc_*` 工具），真正干活的是 Python + Blender。

**能力边界**

- 只读存档，不写存档；
- 需要本机 Blender（≥4.2 LTS，实测 5.2.x）与 Python（opencv-python、numpy）；
- MCprep、BPS 角色骨架、Minecraft 物品库都是第三方资产，不随包分发，必须 `python py/cli.py setup` 装配；
- 出图质量上限受存档地形限制；梯田/树墙存档不会因为调参变成草原。

## 5. 0.6.0 算法：哪些已经真接进工具

### 5.1 `mc_scan` / `py/scan.py`（已接）

- 积分图 O(1) 窗口平坦度；`find_open_ground` 从 O(F·r²) 降到 O(N)；
- Felzenszwalb 距离变换 `inscribed` 内接半径；
- Sobel + RANSAC 坡度过滤 `max_slope=6.0`；
- 9 条 DDA（Amanatides-Woo）射线算 `openness`、`relief`、`horizon`；
- Poisson 间距 + 显式 NMS + NSGA-II 非支配排序/拥挤距离；
- 候选返回 `openness/relief/slope/horizon/inscribed/pareto/crowding`；
- 相机侧过滤 `_camera_side_ok`：默认距离 15，拒绝相机埋进树冠/高地，水面允许。

精度回归：31×31 全平地、`radius=5` 理论 441 个候选，实得 441。

### 5.2 `mc_camera_path` / `py/camera_path.py`（已接）

- A* 8 邻域 → Theta* 视线平滑 → Catmull-Rom 重采样；
- `mc_film` 的 plan 可加 `"camera_path": "path.json"`；`py/film.py` 每镜头复制工程，
  调 `apply_camera_path.py` 覆盖 `camera.location/rotation_euler`；
- `apply_camera_path.py` 接受 `{"points":[[x,z,y],...],"look_at":[x,y,z]}` 或点列；
  点列映射 1..total 帧；固定 look_at 或看向路径前方；
- 手工路径第 12 帧穿山是**路径本身**没做地形避障，不代表接线失败；正式用 `mc_camera_path` 生成。

### 5.3 `mc_search` / `py/shoot_search.py`（已接）

- 低清 `pipeline.shoot(res=480x270,samples=8)` → `vision_check` score →
  `search.bayes_opt` 优化 `yaw/cam_az/dist/lens` → 正式 1280×720；
- 先评基准 `yaw=25,cam_az=200,dist=13.8,lens=105`，低于基准回退；
- `--top N` 会先跑 `step_scan(top_n=N)`，对每个中心用 1280×720/16 samples 评基准；
- 实测：`center=-1,73` 78 分（与基准持平）；top3 自动 27 分（树墙/背面候选把搜索带偏）。
  **当前结论：给 center 更可靠；topN 需要缩略图筛选，不能再直接选。**

### 5.4 `py/search.py`（数值库，已可用）

- `cmaes`：协方差矩阵自适应；
- `bayes_opt`：GP + RBF + EI；
- 二次函数回归：CMA 误差 0.0037，Bayes 0.12；
- 目前只被 `shoot_search` 使用，`mc_shoot` 自身未接。

### 5.5 尚未算法化

- LOD / chunk 高度图缓存 / region 流式读取；
- 面部嘴部 UV、肖像光；
- 视频相机路径的“缩略图/低清候选”筛选（`mc_shoot` 树墙问题同一根因）；
- `mc_map_slim`（按 area 裁 region、删维度/playerdata/stats）尚未实现。

## 6. 提示词动画（0.6.0 新增）

### 6.1 编译

`py/prompt_film.py`

- `RULES` 关键词 → preset：
  `killaura`（杀/战斗/僵尸/光环）、`conduct`（施法/结印/法阵）、`dash`（冲刺/突进）、
  `ride`（骑/坐骑）、`superman`（超人/腾空）、`run`（跑/追/逃）、`walk`（走/散步）、
  `yujian`（御剑/仙侠/飞剑/飞天）。
- `compile_prompt(prompt, blend=None, fps=None, res=None)`：解析秒数、9:16/16:9、相机词，
  生成 1 镜（≤120 帧或“一镜到底”）或 3 镜（全景/中景/近景）；返回 plan + warnings。
- `compile_anim(prompt)`：返回 `{preset,total,fps,warnings}`。
- 相机词：yujian 用 `DSH_YJ_CAM_*`；其它 preset 用通用
  `DSH_ANIM_CAM_AZ_ADD/Z_ADD/RISE_ADD/D_SCALE_ADD/LENS_SCALE_ADD`。
- 保留真实地图：`DSH_ANIM_KEEP_WORLD=1`；贴地：`DSH_ANIM_TERRAIN_SNAP=1`。

### 6.2 执行

- `mc_anim --prompt "5秒跑步"` → 自动选 preset 并渲染；
- `mc_film --prompt "一镜到底，2秒，跑步，低机位" --blend ...` → 自动分镜；
- `py/film.py` 的 `_preset_info(preset)` 同时支持 legacy 脚本和 JSON 配方；
- JSON 配方走 `anim_recipe.py`，产物名读 `blend_name`；
- `anim_kit.py` 读 `DSH_ANIM_RES` / `DSH_ANIM_SAMPLES`，`mc_film` 的 res 对所有 recipe 生效。

### 6.3 已验证 / 未完成

- 已验证：`prompt_anim_run4` 保留地图 + 低机位生效；`prompt_film_test2` 1 秒 480×270
  一镜到底能出 MP4；`run` 动作和 Steve 皮肤正确。
- 未完成：脚底仍略悬空（`motion_ground` 只用 root 单点 raycast，`p.z=z+0.02`）；

  3 镜 1280×720 / 9:16 完整片还没跑；`mc_film` 的 1 秒测试耗时约 12 分钟（构建/渲染都慢）。

## 8. 地图库 / 本地存档 / 上传限制

### 8.1 上传

- 已从 8GB/32GB 收紧为 **单 zip 1GB**（`py/maplib.py DEFAULTS`、`lib/index.js`、
  `lib/client.js`、`lib/map-routes.js`、`cordis.patch.yml` 全部 1024）；
- 解压上限 8GB、单条目 4GB；
- 超限提示改用「读取本地存档」——`.mca` 本身已 zlib，zip/7z 只省 5–15%，不值得为超大包上传。

### 8.2 读取本地存档

- `py/maplib.py:import_local(path, name=None, root=None)`：
  校验 `level.dat`/region，算 bounds/area/thumb，`savePath` 指向原目录，不复制 `.mca`；
  `map_id='m_'+sha256(path)[:12]`。
- `import_local_many(path=None, root=None)`：path 空则扫默认 saves；
  传入世界目录只导它，否则扫子目录里所有带 `level.dat` 的世界；重复走 `map.duplicate`。
- `default_saves_dir()`：`MINECRAFT_SAVES` → `%APPDATA%\.minecraft\saves` → `~/.minecraft/saves`。
- CLI：`map local --path ...`、`map local --all`。
- HTTP：`POST /api/blender-mc/maps/local`（无 path 时 `--all`，返回 `{maps,errors,root}`）；
  `POST /api/blender-mc/maps/pick-local`（PowerShell FolderBrowserDialog，失败回退输入面板）。
- UI：主按钮「读取本地存档」自动扫默认 saves；次按钮「选择 saves 目录」。
  `localStorage['mcbm.localSaves']` 记住上次路径。

**当前未收尾**：`PICK_FOLDER_PS` 的 `Join-Path $env:APPDATA '.minecraft\saves'` 在 JS 模板里
反斜杠转义曾出现 `.minecraftsaves`；picker 初始目录要再核一次。主按钮自动扫描已可用。

## 11. 已知问题 / 未修（按优先级）

| 编号 | 问题 | 根因/位置 | 影响 |
|---|---|---|---|
| P0 | `mc_shoot` 自动扫描会选树墙机位 `(-32,31)` | `_camera_side_ok` 只查相机端点；候选来自 2×2 树缝回退；没有缩略图评分 | 自动出图不可用，需手给 `center` |
| P0 | 皮肤脸无嘴/黑眼窝红嘴 | `mesh face` 材质槽 `Skin`+`Mouth`；隐藏 `mesh lip/mouth/teeth` 后无嘴，隐藏 `mesh face` 脸变洞 | 角色脸不完整 |
| P1 | 提示词跑步脚底悬空 | `motion_ground` root 单点 `p.z=z+0.02`，没有脚底/胶囊采样 | 跑/走看起来在滑 |
| P1 | AI 人偶 3D 皮肤只做头/胸/腰 | `ai_rig.py` 只有 `head_outer/chest_outer/waist_outer` | 手臂/腿仍是平皮 |
| P1 | yujian 相机升空后地形丢失 | 预设相机只升不降/不跟地形；`mc_film` 可选 `camera_path` 但 yujian 没默认用 | 中段空镜 |

| P2 | 本地存档 picker 初始目录可能 `.minecraftsaves` | `PICK_FOLDER_PS` 反斜杠转义 | 次按钮初始位置不对，主按钮不受影响 |
| P2 | LOD / region 流式 / `mc_map_slim` 未做 | — | 超大存档仍慢/占空间 |

## 12. 下一步建议（接手直接干）

1. **树墙机位**：`mc_scan` 候选加“相机—主体全射线 + 树冠净空”评分；`mc_shoot` 在
   `pick_from_save` 后对 topN 各渲 320×180/8 samples，用 `vision_check` 选最好的，
   不再直接回退 2×2 树缝。
2. **嘴部**：不要在 `build_cover.py` 里继续叠隐藏名单。正确做法是重做 `mesh face` 的 UV/材质
   分层（皮肤嘴 + 可选 3D 表情），或用 raycast 把嘴片贴到相机可见脸前表面并加深度偏移/双面材质。
3. **脚底贴地**：把 `motion_ground` 的 root 单点改成双脚/胶囊采样，取两脚最低点；坡面按
   `max(脚底)` 而不是 `root`；加 `DSH_ANIM_FOOT_OFFSET` 微调。
4. **3D 皮肤手臂/腿**：给 `upper_arm/forearm/thigh/shin` 各加 overlay 壳，权重 100% 到对应骨；
   UV 用标准 64×64 sleeve/pants 的 overlay 矩形。
5. **完整 prompt film**：跑一次 3 镜、1280×720、10 秒；检查脚底、画幅、镜头词、转场。
6. **LOD/流式**：chunk 高度图缓存（按 region 读，不整图加载）、粗到细扫描、`mc_map_slim` 裁剪。
