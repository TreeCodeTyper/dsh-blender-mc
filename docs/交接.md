# 交接文档 · dsh-blender-mc

> 面向接手这个插件的人/agent。**先看第 3 节**——三棵源码树是这里最容易出事的地方，
> 历史上两次严重事故都出在「改了 A 树、以为跑的是 A 树」。
>
> 当前版本 **0.5.2**（2026-10-30）。上一版公开可用的稳定版是 0.4.6。

---

## 1. 这个项目是什么

把 Minecraft Java 存档变成 **Blender 封面图 / 10 秒动画 / 分镜成片**，全自动：

```
存档 .mca ──scan──▶ 机位(平地+开阔度) ──export──▶ 世界.obj
                                                   │
              BPS 角色 + 物品 + MCprep 材质 ──build_cover──▶ Blender 渲染
                                                   │
                                    vision_check 审图 ──不合格──▶ 改参数重渲
```

对外是 DSH 插件（`lib/index.js` 注册工具），真正干活的是 Python + Blender 脚本。

**能力边界**
- 只读存档，不写存档；
- 需要本机装 Blender（≥4.2 LTS，实际开发/验收用 5.2.x）与 Python（opencv-python、numpy）；
- MCprep、BPS 角色骨架、Minecraft 物品库都是**第三方资产，不随包分发**，必须
  `python py/cli.py setup` 从用户本地资源目录装配到 `vendor/`；
- 出图质量上限受存档地形限制（梯田型存档不会因为调参变成草原）。

## 4. 运行环境

| 依赖 | 版本/路径 | 备注 |
|---|---|---|
| Blender | ≥ 4.2 LTS；实测 5.2.x | `D:\SteamLibrary\steamapps\common\Blender\blender.exe` |
| Python（宿主） | 3.10+，实测 3.14 | `opencv-python-headless` + `numpy` |
| MCprep | 附加组件 | `%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\MCprep_addon` |
| BPS 角色骨架 / 物品库 / 贴图 | 第三方，装配后进 `vendor/` | 缺失会降级：无骨架=空镜、无贴图=树画不出来 |
| ffmpeg | `vendor/ffmpeg/bin/ffmpeg.exe` | 只动画需要 |

装配：

```powershell
python py/cli.py setup --sources "<资源目录>"   # 先 --dry-run 看会搬什么
python py/cli.py doctor                        # 看缺什么
```

**Blender > Python 的调用链**：`py/blender/*.py` 是被
`blender -b -P build_cover.py` 拉起来的，所以它们只能用 **Blender 自带 Python + bpy**，
不能 `import cv2`。一旦顶层 `import cv2`，整个 `blender/` 目录在 Blender 里全崩。

## 5. 数据目录与环境变量

数据根：`C:\Users\Admin\.dsh\blender-mc\`

```
maps/<id>/world/     上传的存档（map 命令管理）
skins/               皮肤 PNG
vendor/              rig / item / textures / ffmpeg（gitignore）
out/                 产物
```

**路径类（pipeline 负责注入，不要手写死）**

| 变量 | 含义 |
|---|---|
| `DSH_MC_MAPS` / `DSH_MC_SKINS` | 地图库 / 皮肤库根目录 |
| `DSH_MC_VENDOR` | vendor 根 |
| `DSH_MC_RIG` | BPS 角色骨架 .blend |
| `DSH_MC_ITEM(+_R/_L)` | 物品库 .blend 与双手物品 |
| `DSH_MC_TEXTURES` | 方块贴图目录（0.5.1 起由 `resolve_assets()` 注入） |
| `DSH_MC_FFMPEG` | ffmpeg 可执行文件 |

**画质类（0.5.x 常用，全部有默认值，不设就用默认）**

| 变量 | 默认 | 作用 |
|---|---|---|
| `DSH_ENGINE` | `BLENDER_EEVEE` | 改 `CYCLES` 会慢一个数量级，慎用 |
| `DSH_SAMPLES` / `DSH_RES_X/_Y` | 192 / 1280×720 | 采样与尺寸 |
| `DSH_LOOK` | `AgX - Punchy` | AgX 的 look（5.2 的 OCIO 里查不到 looks 段，失效时用 A/B 验证） |
| `DSH_EXPOSURE` | 0.05 | 曝光 |
| `DSH_SKY` | 0.12 | 天空强度（0.4.x 用 0.03 + Standard，才需要限幅补丁） |
| `DSH_SUN_ELEV` / `DSH_SUN_ANGLE` | 14° / 340° | 太阳高度/方位（刻意压到黄昏，出暖调侧光） |
| `DSH_KEY_SCALE` / `DSH_FILL_SCALE` / `DSH_RIM_SCALE` | 1.0 | 三点灯能量倍率（同比例缩放，灯位不变） |
| `DSH_FOG` / `DSH_CLOUDS` | 0.0012 / 1 | 雾密度、云 |
| `DSH_CAM_H` / `DSH_DIST` / `DSH_LENS` | 1.55 / 15.0 / 105 | 机位高、距离、焦距 |
| `DSH_POSE` | `action` | `hero/raise/guard/legacy/action` |
| `DSH_TREES` | 0（工具默认 12） | 背后种几棵原版形状的树 |
| `DSH_POST` / `DSH_GLARE` / `DSH_VIGNETTE` / `DSH_GRADE_SAT` | 1/1/1/1 | 后期合成器开关与强度 |
| `DSH_MC_AUTO_AZ` | 1 | 视线方位是否按地形自动挑 |

完整清单（含动画、物品、骨骼微调）：`grep -o "DSH_[A-Z_0-9]*" py/blender/build_cover.py | sort -u`。

## 6. 渲染管线与画质参数

**五步**（`pipeline.py`）：`scan → export → blender(build_cover) → vision_check → auto_adjust`
（不合格按问题类型改参数重渲，最多 `--attempts` 次。）

**0.5.x 相对 0.4.x 的画质改动**（改这版全靠这些）

| 项 | 0.4.x | 0.5.2 | 为什么 |
|---|---|---|---|
| 后期合成 | 无（EEVEE 5.x 已无 `use_bloom`） | `post_grade.py`：Bloom(thr .62/str .30/size .55)+饱和 1.16+椭圆暗角 | 直出图永远「平、灰」 |
| 环境光遮蔽 | `fast_gi_options` 结构在 5.2 不存在 → 整段被跳过（`fast_gi_distance=0`） | 扁平属性赋值：`fast_gi_distance=3.0 / ray_count=4` | 脚底没有接触阴影 = 悬浮 |
| 布光 | 三点灯写死在世界坐标，远到 3.7 m 且 Key:Fill≈1.6:1 | 灯位改成**相机相对**（Key 前右上 / Fill 前左 / Rim 后右高），Key 320W s1.7、Fill 45W s2.6、Rim 1500W s0.8 | 平光没人味；Rim 才有轮廓 |
| 天空/雾 | aerosol 1.7 + fog 0.0026 → 远处洗成奶白 | aerosol 0.45、fog 0.0012、颜色 (0.80,0.88,1.00)、aniso 0.45 | 颜色被雾吃掉就没法调色 |
| 材质高光 | `Specular IOR Level=0` | 0.45、roughness 0.62，钻石/铁类按金属度上调 | 全场景零高光 = 塑料感 |
| 取景 | 只要方位不被墙挡就选 | 另加：地形仰角 ≤8° 硬过滤、背后空旷加分、迎太阳扣分 | 0.4.x 会正对 42.8° 的土崖 |
| 姿态 | 站桩 `hero` | `action`（躯干转 18°、举剑、分腿） | 「人物动作僵硬」 |
| 机位 | 距离 17、高 1.30 | 距离 15、高 1.55 | 主体更大、地平线更高 |
| 武器 | `basis_from()` 左手系（det=-1）→ 剑整个镜像 | `col0=(a-b)/√2, col1=(a+b)/√2`，det=+1 | 镜像导致法线内翻、刃口永不高光 |

**注意**：所有「亮度/能量」类改动必须**成组**生效。只提亮 → 更亮更奶白；
只抬 spec → 不出高光；只有「小而亮的 Rim + AgX + 后期」三者一起，才会同时出现
高光、轮廓、对比。（A/B 实测记录在 `_scratch\诊断_1030\审计总报告.md`。）

## 7. 审图（vision_check）到底在测什么

`py/vision_check.py` 是**代理指标**，不是美学评价：

- 朝向：头部区域皮肤色占比 → 判正脸/背面；
- 接地：脚底下方与旁边地面的色差 + 阴影强度；
- 曝光：死白/死黑/p1-p99 动态范围；
- 布光：地面灰阶方差；
- 构图：主体占比/位置/留白；
- 景深：背景高频能量。

评分：PASS ≥80 / WARN ≥60 / FAIL <60，权重偏「主体朝向 + 曝光 + 构图」。
`auto_adjust` 只会改 5 类问题（曝光/距离/朝向/雾/灯），**不会**改取景创意。

**已知误报**（看到这些不要慌）
- `阴影强度 0.0`：AO 关闭时永远报，0.5.x 已开 AO，报错时先看 `_封面日志.txt` 的 fast_gi 行；
- `天空没有任何高光斑 (hot_ratio=0)`：阴天/平光/大面积云时必然报，画面没问题是正常的；
- **PASS ≠ 好看**：审图 PASS 的图仍可能背景杂乱，最终要靠人眼/图像模型判断。

## 8. 版本规则与发布

**SemVer 在本仓库的落地**

| 改动性质 | 级别 | 例子 |
|---|---|---|
| 只修 bug，出图观感不变 | PATCH | 修一个崩溃、修路径拼接 |
| 默认观感/行为变化、新功能 | **MINOR** | 0.5.0（布光/取景/姿态默认值全变 + 后期链路）、0.5.1、0.5.2 |
| 破坏兼容（CLI 参数删除、配置不兼容） | MAJOR | 目前 0.x，按 minor 处理 |

> 0.4.10 这个号是错的：它包含新功能与默认值变更，必须当 MINOR 发 → **0.5.0**。

**发版流程**

```powershell
# 1. 仓库干净、main 分支
git status
# 2. 改版本号（package.json + CHANGELOG 顶部条目）
# 3. 一键发布（会做冒烟 + 卫生检查 + npm pack --dry-run + publish）
powershell -ExecutionPolicy Bypass -File scripts\release.ps1
#    只推 git：      -SkipPublish
#    只发 npm：      -SkipPush
#    干跑检查：      -DryRun
```

发布后还要回到本机：`python scripts/install_to_profile.py`（或拷目录），否则生产的还是旧版。

**坑**
- npm 发布前把 `npm_config_cache` 指到工作区内（`$env:npm_config_cache="$PWD\.npmcache"`），
  否则默认缓存目录被沙箱拒绝 → `EPERM npm-cache`；
- `npm pack` 的 `files` 白名单别漏：`py/**/*.py`、`lib`、`docs/*.md` 都在列表里，
  新增目录记得加；
- 有 2FA 时 `release.ps1 -Otp 123456`。

## 9. 改完之后必须跑的验收（4 条）

```powershell
cd <仓库>
python py/cli.py doctor                     # 依赖齐不齐
python py/cli.py check <一张图>             # 审图模块没坏
python py/cli.py shoot "<存档world目录>" --area x0,x1,z0,z1 --res 640x360 --samples 48 --attempts 1
# ↑ 必须看到 "素材: textures=✓ / rig=✓ / item=✓"，并且出图不是空镜
git -C . status --porcelain                 # 只应有你预期的改动
```

判读：`素材:` 四个勾缺一个，就是 §5 的路径注入断了；出图是空镜 = 骨架没找到；
树林不出现 = `DSH_MC_TEXTURES` 空。

## 11. 排障速查

| 症状 | 根因 | 处理 |
|---|---|---|
| `[sandbox: file access denied under workspace-write mode]` | 写 `.dsh` 下的生产目录 | 用 `sandbox_permissions: danger-full-access` 单次提权，或改仓库再 `install_to_profile.py` |
| 启动时打印「没装 BPS 角色骨架 / 物品库 / ffmpeg」，但图里角色明明有 | CLI 直接跑时 `resolve_assets()` 的结果没注入子进程（0.5.1 已修） | 看 `素材:` 行；四个 ✓ 才叫接上了 |
| 树林一棵没种 | `DSH_MC_TEXTURES` 空 / 贴图目录不存在 | `python py/cli.py setup`，或看 0.5.1 的 MCprep 资源包回退路径 |
| Blender 里 `import cv2` 崩 | `py/blender/*.py` 跑在 Blender 自带 Python | 把 cv2 的 import 挪进函数体或挪出 `blender/` |
| 改代码没生效 | 编辑的是仓库，跑的是生产 | 见 §3，重装再验证 |
| `SyntaxError: (unicode error) 'unicodeescape'` | 内联 Python 里写了 Windows 路径没加 `r""` | 用 `r"C:\..."` 或写成 .py 文件跑 |
| 文件被写成 CRLF，改不动 | Windows 上 Python `open()` 默认换行转换 | 用 `newline=""` 并显式写 `\n`，或统一 `.gitattributes` |
| `Invalid package config` / `Unexpected token '\uFEFF'` | PowerShell 5.1 的 `Get-Content/Set-Content` 按 ANSI 读写，把 UTF-8 转成乱码并加 BOM | **不要用 `Set-Content` 改 JSON**：`[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`，或直接从生产目录拷回干净副本 |
| 渲染 3 分钟+ | EEVEE 首帧编译着色器 | 属正常；同场景第二次会快很多 |
