# 自带模型（Bring Your Own Models）

> 插件只提供**格式转换 + 摆放进场景**这两件事。模型、贴图全部由使用者自备，
> 插件不附带、不联网下载、不内置任何作品名。

## 能力边界

| 插件做 | 插件不做 |
|---|---|
| 把 Bedrock 几何 `.geo.json` + 贴图转成 OBJ（`py/bedrock.py`） | 不附带任何模型 / 贴图 |
| 递归扫描你指定的目录，按 `identifier` 命名、猜贴图（`py/extract.py`） | 不联网下载素材 |
| 把 OBJ 摆进封面场景：缩放、朝向、相对机位的前后/左右/高度（`build_cover.py`） | 不判断素材授权 |
| 写 `models.json` 清单（来源、面数、包围盒），方便复现 | 不替你分发产物 |

## 三步

### ① 解包你自己的资源包

资源包 / 整合包里通常在这几个位置：

```
assets/<namespace>/geo/*.geo.json        ← Bedrock 几何
assets/<namespace>/textures/entity/*.png ← 对应贴图
```

解包后不用整理，插件会递归找。

### ② 提取成 OBJ

```powershell
python py/cli.py extract "D:\资源包解包目录" --out .\模型
```

先看会转什么（不写文件）：

```powershell
python py/cli.py extract "D:\资源包解包目录" --out .\模型 --list
```

只转其中一部分：

```powershell
python py/cli.py extract "D:\资源包解包目录" --out .\模型 --filter barrel
```

套一段动画姿势（模型是绑定姿势时有用）：

```powershell
python py/cli.py extract "D:\资源包解包目录" --out .\模型 --filter golem `
  --anim "...\animations\golem.animation.json" --anim-name ground_idle
```

产物：

```
模型/
  models.json                 ← 清单（来源 / 面数 / 包围盒 / 失败项）
  barrel/barrel.obj
  barrel/barrel.mtl
  barrel/barrel.png
  barrel/model.json           ← 单个模型的元信息
```

### ③ 指给渲染用

**方式 A：描述文件（数量不限）**

```json
[
  {"name": "木桶", "obj": "D:/模型/barrel/barrel.obj", "tex": "D:/模型/barrel/barrel.png",
   "scale": 1.0, "back": 4.0, "side": 0.0, "z": 0.0, "yaw": 0.0}
]
```

```powershell
$env:DSH_MODELS = "D:\模型\models-list.json"
python py/cli.py shoot "...\存档" --area -2100,-1600,-1400,-900 --out .\出图
```

**方式 B：三个槽位环境变量**

```powershell
$env:DSH_MODEL1_OBJ = "D:\模型\barrel\barrel.obj"
$env:DSH_MODEL1_TEX = "D:\模型\barrel\barrel.png"
$env:DSH_MODEL1_SCALE = "2"      # 放大一倍
$env:DSH_MODEL1_BACK = "5"       # 站到机位中心后方 5 格
$env:DSH_MODEL1_SIDE = "-2"      # 左偏 2 格
$env:DSH_MODEL1_YAW = "90"       # 转 90°
```

在 DSH 里也可以写进插件 config（`cordis.patch.yml`）：

```yaml
- id: blender-mc
  name: 'dsh-blender-mc'
  config:
    models: 'D:\模型\models-list.json'
```

### 摆放参数

| 键 | 含义 | 缺省 |
|---|---|---|
| `name` | 日志与材质里显示的名字 | `model1` |
| `obj` | OBJ 路径（相对路径按描述文件所在目录解析） | 必填 |
| `tex` | 贴图路径，留空则用 OBJ 自带材质 | 空 |
| `scale` | 缩放倍数（OBJ 已是方块单位时用 1） | 1.0 |
| `back` | 在机位中心**后方**多少格（越大越远、在角色身后） | 4.0 |
| `side` | 左（负）/ 右（正）偏移，相对视线 | 0.0 |
| `z` | 抬高 / 下压，0 = 底面贴地 | 0.0 |
| `yaw` | 绕竖轴旋转角度 | 0.0 |

## 常见问题

**模型躺倒了 / 陷进地里**
OBJ 导入器会带一个 Y-up → Z-up 的旋转。插件已经在导入后 `transform_apply` 烘焙掉它，
正常情况下不会躺倒。如果还躺，多半是导出时坐标系就不是 Y-up —— 在 Blender 里手动校一遍，
或把 OBJ 重新导出成 Z-up。

**模型太大 / 太小**
Bedrock 几何导出时已按 16 像素 = 1 方块换算。偏大偏小先用 `scale` 调，
不要改 OBJ —— 保持"一个模型 = 一份原始文件"，方便换场景复用。

**贴图错位**
先确认贴图尺寸和 `.geo.json` 里的 `texture_width / texture_height` 一致；
再确认几何用的是 box UV 还是 per-face UV（两种插件都支持，但贴图必须对得上）。

**模型穿地**
`back` 越大，模型越靠后；如果后方地形更高，底面会贴到那层地面。
先渲 `--preview` 或小分辨率（`$env:DSH_RES_X=640`）验证位置，再跑正式图。

**提取出来少零件**
零厚度的 cube（翅膀、薄片、贴图特效）是合法的，插件会把它们钳到极小厚度渲成薄片，
不会丢。如果整块缺失，看 `models.json` 里的 `cubes` 是多少 —— `done/total` 不一致说明几何本身有问题。

## 授权与合规

这不是法律意见，只是本项目的处理原则：

1. **插件不分发素材。** npm 包的 `files` 白名单只有代码和文档，CI 里有一条
   `hygiene` 会拦下 `vendor/`、`.blend`、渲染产物、模型/贴图等资产提交。
2. **提取产物落在你自己指定的目录**，插件不上传、不外发。要不要分发、能不能商用，
   取决于原素材的许可 —— 「整合包能玩」不等于「模型能商用」。
3. **公开发布前自己确认授权**：查资源包 / 模组的 LICENSE 或作者声明，
   商用、二创、二次分发是三件不同的事。
4. **建议留一份来源记录**：`models.json` 里已经记了来源路径和 identifier，
   再补一条作者 / 许可信息，日后好追溯。
5. **插件代码里不出现任何作品名**。能力是通用的：任何符合 Bedrock 几何格式的模型都能进来。
