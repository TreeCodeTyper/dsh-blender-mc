面向**维护者**。普通用户不需要看这篇。

## 前置条件

| | 需要什么 |
|---|---|
| ✅ | GitHub 仓库（公开） |
| ✅ | npm 账号（发布到 npm registry，DSH 插件市场从那里读） |
| ✅ | Node ≥ 20 |
| ✅ | 仓库里有 `LICENSE` / `README.md` / `package.json` |

## 一、首次发布

### 1. 确认仓库地址是对的

`package.json` 里这三项已经填好了，**发布前扫一眼**：

```jsonc
{
  "repository": {
    "type": "git",
    "url": "https://github.com/TreeCodeTyper/dsh-blender-mc"
  },
  "homepage": "https://github.com/TreeCodeTyper/dsh-blender-mc#readme",
  "bugs": { "url": "https://github.com/TreeCodeTyper/dsh-blender-mc/issues" }
}
```

**改了仓库名或 GitHub 用户名的话，这里也要跟着改**（README、CONTRIBUTING、
CHANGELOG 里也有同样的链接）。

CI 只检查这些字段**存在**，不检查内容对不对 —— 内容得自己确认。

### 2. 确认市场必需字段齐全

DSH 插件市场读 `package.json`，**这几个字段缺一个就上不了架**：

| 字段 | 值 | 说明 |
|---|---|---|
| `name` | `dsh-blender-mc` | npm 包名，全小写 |
| `version` | `0.1.0` | 语义化版本 |
| `description` | 一句话 | **会显示在市场的插件卡片上**，写清楚能干什么 |
| `type` | `module` | ESM |
| `main` | `lib/index.js` | 入口 |
| `exports` | `{ ".": {...}, "./cordis.patch.yml": ..., "./package.json": ... }` | ⚠️ **`./cordis.patch.yml` 必须导出**，否则加载器找不到补丁 |
| `license` | `MIT` | |
| `repository` | GitHub 地址 | |
| `publishConfig.access` | `public` | 否则 scoped 包默认私有 |
| `engines.node` | `>=20` | |
| `dsh.bundle.patch` | `./cordis.patch.yml` | ⚠️ 缺了**插件不会被加载** |
| `dsh.manifestVersion` | `1` | ⚠️ 缺了市场不认 |
| `files` | 见下 | ⚠️ **绝不能包含 `vendor/`** |
| `icon` | `./icon.svg` | 市场卡片图标 |

### 3. `files` 白名单（重要）

```json
"files": [
  "lib", "py", "docs",
  "cordis.patch.yml", "README.md", "README.en.md",
  "LICENSE", "CHANGELOG.md", "icon.svg"
]
```

**`vendor/` 必须在外面。** 原因有两条：

1. **版权** —— 里面是 BPS Rig、Minecraft Item Rig 等第三方资产，不属于本项目，
   不该随 npm 包再分发
2. **体积** —— 16 MB 的 `.blend` 会让每次 `npm install` 都多下载这么多

使用者跑 `python py/cli.py setup` 自己装配。CI 里有一条检查专门拦这个。

### 4. 本地验证

```bash
# 外壳测试（不需要 Blender，秒级）
node scripts/smoke.mjs

# 看看 npm 包里到底会装什么 —— ★ 重点确认没有 vendor/
npm pack --dry-run

# 检查 package.json 的市场字段
python - <<'PY'
import json
p = json.load(open('package.json', encoding='utf-8'))
need = ['name','version','description','type','main','exports','license',
        'repository','publishConfig','engines','dsh','files']
print('缺:', [k for k in need if k not in p] or '无')
print('dsh.bundle.patch:', p['dsh'].get('bundle', {}).get('patch'))
print('dsh.manifestVersion:', p['dsh'].get('manifestVersion'))
print('files 里有 vendor 吗:', any('vendor' in f for f in p['files']))
PY
```

### 5. 打 tag 并发布

```bash
# 确认 main 是最新的、CI 是绿的
git checkout main && git pull

# 打 tag（版本号要跟 package.json 一致）
git tag -a v0.1.0 -m "v0.1.0 首个可用版本"
git push origin v0.1.0

# 发布到 npm
npm login
npm publish --access public
```

发布成功会返回包地址：`https://www.npmjs.com/package/dsh-blender-mc`

### 6. 在 GitHub 上建 Release

把 `CHANGELOG.md` 里对应版本那段贴进去，附上几张效果图。

### 7. 上架到 DSH 插件市场

包发到 npm 之后，在 DSH 里：

1. 打开 **设置 → 插件市场**
2. 搜索 `dsh-blender-mc`

如果搜不到，说明市场的索引还没收录。等一会儿再试；
还是不行就在市场的仓库里开 Issue 请求收录，附上 npm 包名。

## 二、后续发版

```bash
# 1. 更新 CHANGELOG.md（把 Unreleased 的内容挪到新版本号下）
# 2. 改 package.json 的 version
#    语义化版本：
#      patch  0.1.0 → 0.1.1   修 bug
#      minor  0.1.0 → 0.2.0   加功能，向后兼容
#      major  0.1.0 → 1.0.0   破坏性改动（改参数名、改默认值）
# 3. 提交
git add -A
git commit -m "chore(release): v0.2.0"
git tag -a v0.2.0 -m "v0.2.0"
git push origin main --tags

# 4. 发布
npm publish --access public
```

## 三、版本号怎么定

**这是插件，`version` 影响用户会不会自动拿到更新。** 判断标准：

| 改动 | 版本 | 例子 |
|---|---|---|
| 修 bug，不改接口 | **patch** | 修中文路径读图失败 |
| 加功能，向后兼容 | **minor** | 新增 `--res` 参数；新增审图判据 |
| **改默认值 / 改参数名 / 改输出路径结构** | **major** | `--dist` 默认从 11.2 改成 9.0（用户手上的命令行为会变） |

> ⚠️ **改默认值算破坏性改动。** 用户写的命令没变，出来的图变了 —— 这比改参数名更隐蔽。
> 本项目历史上改过好几次默认值（`sky` 从 0.5 到 0.03、`sink` 从 0 到 0.06），
> 每次都在 CHANGELOG 里写清了为什么。

## 四、CI 会拦什么

`.github/workflows/ci.yml` 在 PR 和推 `main` 时跑：

| Job | 检查 |
|---|---|
| **smoke** | 模块能 import、三个导出都在、6 个工具都注册了、`description` 长度合理、dispose 正常释放 |
| **python** | 全部 `.py` 语法、关键模块能 import、审图模块能读图跑分、条件检查能给出安装指引 |
| **hygiene** | **没有提交第三方资产**；没有渲染产物；`package.json` 市场字段齐全（含 `manifestVersion`、`files` 不含 `vendor`）；文档内部链接有效 |

**`hygiene` 那个"没有第三方资产"检查是最重要的** —— 它会拦住任何不小心
`git add -f vendor/` 的提交。

## 五、npm 的 2FA 拦截 ← 最容易踩的一个

如果 npm 账号开了两步验证（2FA），`npm publish` 会报：

```
npm error code E403
npm error 403 Forbidden - PUT https://registry.npmjs.org/你的包名
npm error 403 Two-factor authentication or granular access token
npm error 403 with bypass 2fa enabled is required to publish packages.
```

**原因**：npm 的 Classic Token 有三种类型，**只有一种能免验证码发布**：

| Token 类型 | 能发布吗 | 要验证码吗 |
|---|---|---|
| Read-only | ❌ 不能 | — |
| **Publish** | ✅ 能 | **要** ← 多数人第一次建的是这个 |
| **Automation** | ✅ 能 | **不要** ✅ |

### 解法 A：现场给验证码（最快）

手机上打开验证器看 6 位数字，然后：

```powershell
npm publish --access public --otp=123456
```

用本仓库的脚本也行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Otp 123456
```

> ⚠️ 验证码 **30 秒过期**，看到提示再打开验证器来得及。
> OTP 用过一次就作废，下次发布要重新给。

### 解法 B：换成 Automation Token（一劳永逸）

1. 打开 <https://www.npmjs.com/settings/~/tokens>（`~` 换成你的 npm 用户名）
2. **Generate New Token** → **Classic Token**
3. 类型选 **Automation**（⚠️ 别选 Publish）
4. 复制 token（`npm_` 开头）
5. 配到本地：
   ```powershell
   npm config set //registry.npmjs.org/:_authToken=你的token
   ```
6. 之后 `npm publish` 不用再给验证码

### 解法 C：Granular Access Token

如果你用的是新版 Granular Token（不是 Classic），创建时必须：

- **Packages and scopes**: Read and write
- **✅ Bypass 2FA** ← 不勾一样会被拦

### 几个坑

- **`npm publish --dry-run` 不会触发 2FA 检查** —— 它通过不代表真发布能通过
- `npm whoami` 只验证 token 能读，**不代表能写**
- OTP 输错 3 次会被临时锁定，等几分钟再试

## 六、发不出去时

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 **403 + 提到 2FA** | token 类型不对 | 见上一节：给 `-Otp` 或换 Automation Token |
| 报 402 | 没登录 / 没权限 | `npm login`；scoped 包要 `--access public` |
| 报 403 且**没提 2FA** | 包名被占了 | 改 `name`，或加 scope（`@你的名字/dsh-blender-mc`） |
| 包体积异常大 | `files` 里写的是裸目录名（如 `py`），把 `__pycache__` 带上了 | 改成 glob（`py/**/*.py`）；`npm pack --dry-run` 看清单 |
| 装了但工具不出现 | `dsh.bundle.patch` 缺失或路径不对 | 检查 `package.json` 和 `exports` |
| 装了但市场搜不到 | npm 索引延迟 / 未收录 | 等几分钟，或去市场仓库开 Issue |
| 用户装了但报 `cannot get property without inject` | `apply` 里用了没在 `inject` 里声明的服务 | 加进 `export const inject` |

## 七、给市场卡片写好的描述

`description` 是用户在市场里**唯一会读的一行字**。别写成：

> ❌ "Minecraft Blender 插件"

写成：

> ✅ "Minecraft 存档 → Blender 封面 / 动画。自动找机位、搭场景、渲染，并用 OpenCV 自动审图（渲完自己检查朝向/接地/曝光/布光，不合格自动调参重渲）。"

**要素**：输入是什么 → 输出是什么 → 最特别的一点是什么。
