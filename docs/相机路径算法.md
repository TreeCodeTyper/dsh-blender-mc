# 相机路径算法（0.6.0）

`py/camera_path.py` 把“相机怎么走”从预设关键帧改成可计算路径：

1. **A\***：8 邻域，代价 = 步长 × (1 + 2×坡度)；只走有效地表。
2. **Theta\***：`theta_smooth` 从父节点向当前节点做视线检查，能直连就跳过中间栅格，
   去掉 A* 的锯齿。
3. **Catmull-Rom**：对稀疏路径按 `samples_per_seg` 重采样，得到平滑轨迹。

## 用法

```bash
python py/camera_path.py <save> --area=-100,100,-100,100 \
  --start=-68,65 --goal=43,83 --out=path.json
```

输出：

```json
{"start":[-68,65],"goal":[43,83],"points":[[x,z,y], ...]}
```

`y` 默认是地表 + 2.5，可传 `height_offset`。

## 接入 `mc_film`

分镜表里加 `"camera_path": "path.json"`（绝对值或相对 plan 的路径）即可：

```json
{"title": "...", "fps": 24, "res": "480x270", "blend": "...",
 "camera_path": "path.json",
 "shots": [{"id": "S1", "preset": "run", "range": [1, 48]}]}
```

- 每个镜头复制一份封面工程，再把路径点映射到该镜头的 `range` 帧区间；
- `path.json` 有 `look_at` 就固定看它；没有就逐帧对准骨架 `Head`（找不到骨架时
  用 armature 原点 +1.5），**不再沿路径切线看**——这是 0.6.0 修掉“第 1 帧整屏蓝天”的原因；
- 路径起点最好在角色侧后方，别正好落在角色脚下，否则首帧主体在画面外。

## 边界

- 路径只保证“沿地表可走、坡度代价低”，不保证镜头不穿树；穿树检查仍需
  把 `TopMap.any` 纳入代价，或渲染后人工/自动复核。
- `plan_camera_path` 无解时 CLI 返回 1，但仍会写一个 `points: []` 的 json，且不打印
  失败原因；按返回码判断，别只看文件是否生成。
