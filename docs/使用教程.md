## 你会得到什么

输入：一个 Minecraft Java 版存档目录。

输出：
- 一张 **1280×720 的封面图**（角色站在你地图的真实地形上，有光照、有影子）
- 或者一段 **10 秒动画**（角色挥剑 + 环绕的发光能量环）

全程你不需要打开 Blender 界面。

## 第 1 步：找到你的存档

存档在 Minecraft 的 `saves` 目录下：

| 系统 | 位置 |
|---|---|
| Windows | `%APPDATA%\.minecraft\saves\<存档名>` |
| 启动器 | 有些启动器（PCL2、HMCL）会存在自己的目录里，在启动器里能查到 |

**判断对不对**：进去看有没有 **`region`** 文件夹，里面是 `.mca` 文件。

```
我的世界/                    ← ★ 就是这个目录
├── region/
│   ├── r.0.0.mca
│   └── r.-1.0.mca
├── level.dat
└── playerdata/
```

> **记下这个路径**，后面要用。路径里有中文没问题，本插件处理过中文路径。

> ⚠️ **基岩版不支持**。基岩版的存档里是 `db` 文件夹和 `.ldb` 文件，不是 `.mca`。

## 第 1.5 步：把存档传进 DSH（推荐）

上面的路径你当然可以每次都手填，但更省事的做法是把存档**传进 DSH**，以后出图只要报名字。

**入口**：DSH 左侧栏最下面 **设置（齿轮）** → 左侧列表里找 **「背景地图」**（排在「技能」和插件市场之间）。

**怎么传**：

1. 把 `.zip` 拖到面板中间的虚线上，或者点 **选择文件**。
2. 传完会自己解压、识别存档、生成缩略图。大包（整合包地图几 GB）要等一会儿，进度条会一直走。
3. 出现一张卡片就说明入库了，卡片上有：缩略图、名字、包里大小、坐标范围（X/Z 最小最大值）、上传时间。

**卡片上的三个按钮**：

| 按钮 | 作用 |
|---|---|
| 设为默认 | 之后不指定地图时用它 |
| 重命名 | 改成你认得出的名字，例如「大草原出生点」 |
| 删除 | 从库里移除（存档目录会进回收站 7 天，误删可找回） |

**传完之后怎么用**：出封面时不用再给 `save` 和 `area`，直接给 `map`：

```
mc_shoot({ map: "大草原出生点", out: "E:\\出图\\大草原" })
```

插件会自己去库里把这条记录换成存档目录，并用上传时算好的推荐区域开机位。
想找机位也一样：`mc_scan({ map: "大草原出生点" })`。

**规则与限制**：

- 只认 **Java 版**存档（包里要有 `level.dat` 和 `region/*.mca`）；整个整合包一起压进来也行，插件会自己在包里找存档。
- 同一个包传两次会提示「已经上传过了」（按内容哈希判重），不会占双份空间。
- 上传 zip 单包上限默认 1 GB、解压后 8 GB（可在插件配置里调 `maxUploadMb`）；更大的地图请用「读取本地存档」，不复制 `.mca`。
- 数据放在 `%USERPROFILE%\.dsh\blender-mc\maps\`，一个地图一个子目录，直接拷走/备份都行。
- 命令行等价写法：`python py/cli.py map import --zip 地图.zip --name 大草原出生点 --json`。

## 第 1.6 步：换人物皮肤（可选）

渲染默认用的是原版 Steve。想换成自己的皮肤，不用改代码、不用改文件：

1. 打开发 **设置 → 背景地图**（同一个页面，往下滚就是「人物皮肤」）
2. 把 `64×64` 的皮肤 PNG 拖进虚线框（或点一下选文件）
3. 上传后会在下面生成一张卡片，显示缩略图、尺寸、大小；
   点 **设为默认** 以后每张图都用它，点 **删除** 就回到原版 Steve

也可以在出图时临时指定一张，不影响默认值：

```text
在「方可梦世界」里给史蒂夫换上「测试皮肤_红衫」出三张封面
```

对应工具参数是 `skin`（皮肤库名字 / `s_` 开头的 id / PNG 绝对路径都行）：

```json
{ "map": "方可梦世界", "skin": "测试皮肤_红衫" }
```

命令行等价写法：

```bash
set DSH_SKIN=E:\皮肤\我的皮肤.png
python py/cli.py shoot "C:/Users/你/.dsh/blender-mc/maps/m_xxx/world" --area 0,512,0,512
```

**限制**：

- 只支持 **经典模型（4 像素臂）** 的 `64×64` 皮肤；`1.8` 的 Slim（3 像素臂）
  和 1.7 的 `64×32` 老皮肤贴上去会错位
- 文件 ≤ **2 MiB**，必须是 PNG
- 皮肤存在 `%USERPROFILE%\.dsh\blender-mc\skins\`，删插件不会丢

## 第 2 步：装 Blender

1. 打开 <https://www.blender.org/download/>
2. 下载 **Windows Installer (.msi)**
3. 双击安装，一路下一步

> `C:\Program Files\Blender Foundation\...`、Steam 库、以及系统 `PATH`。
> 都没有的话，用 `--blender "路径"` 显式指定。

## 第 3 步：装本插件

### 如果你是 DSH 用户

DSH → **设置** → **插件市场** → 搜索 `dsh-blender-mc` → 安装 → **开新会话**

> ⚠️ **必须开新会话**。插件是在会话启动时加载的，当前会话刷新也不会生效。

#### 装完 DSH 打不开（双击没反应 / 窗口一闪就没）

**0.2.1 之前的版本有这个问题，0.2.1 已修掉。** 已经中招的机器不用重装 DSH，一条命令就能修：

```bash
cd <插件目录>
python scripts/repair_profile.py            # 只体检，看看补丁层是不是坏的
python scripts/repair_profile.py --apply    # 自动修，改之前会备份
```

修好之后再双击 DSH 就能打开，日志里也能看到修了什么。想回滚：

```bash
python scripts/repair_profile.py --restore
```

出问题的原因是 profile 里的 `cordis.patch.yml` 被写成了非法 YAML（文件里同时出现 `[]` 占位符和一个 `- id:` 条目，或者只剩注释没有 `[]`）。DSH 启动时解析这个文件失败，会把异常一路抛到主进程，直接退出 —— 所以看起来像"一装就废"。

**自己手改这个文件时的两条铁律**：

1. 一个文件只能有**一份**顶层列表。开头模板里的 `[]` 是占位符，要加条目就把它删掉或注释成 `# []`；
2. 没有任何条目时**必须留一个 `[]`**。空文件或只有注释同样会让 DSH 起不来。

### 如果你想当命令行工具用

```bash
git clone https://github.com/TreeCodeTyper/dsh-blender-mc.git
cd dsh-blender-mc
pip install opencv-python numpy
```

后面的命令都用 `python py/cli.py <子命令>` 的形式。

## 第 4 步：检查缺什么

```bash
python py/cli.py doctor
```

**这是最重要的一步。** 它会检查所有东西，而且**缺什么就告诉你怎么装**：

```
======================================================================
运行条件检查
======================================================================
  ✅ Python 依赖（opencv-python + numpy）   cv2 5.0.0 / numpy 2.5.1
  ✅ Blender                            D:\...\blender.exe
  ⚠️  MCprep 附加组件                        未安装
  ⚠️  BPS 角色骨架                          没找到
  ⚠️  MC 方块贴图目录                          没找到
  ⚠️  ffmpeg                             没找到
```

每一项缺失都会展开成完整的安装指引：

```
  ┌─ MCprep 附加组件
  │  【是什么】方块材质处理。存档导出的 OBJ 里材质名就是 MC 贴图名，
  │            MCprep 会把它们变成能渲染的材质，并自动做生物群系染色
  │  【没它会怎样】世界会渲染成灰白或纯色 —— 草地不会变绿
  │  【去哪下】https://github.com/Moo-Ack-Productions/MCprep
  │  【怎么装】
  │      方法 A（推荐，插件代装）：把 MCprep 的 zip 放到任一资源目录，然后
  │           python py/cli.py setup <资源目录>
  │      方法 B（手动）：Blender → 编辑 → 偏好设置 → 附加组件 →
  │           右上角下拉 → 从磁盘安装 → 选那个 zip → 勾选启用
  └─
```

### 必需 vs 可选

| | 组件 | 缺了会怎样 |
|---|---|---|
| **必需** | Python 依赖 | 跑不了 |
| **必需** | Blender | 跑不了 |
| **必需** | MCprep | 草地不变绿，基本不能用 |
| 可选 | 角色骨架 | **只出风景空镜**，没有角色 |
| 可选 | 物品库 | 角色空手 |
| 可选 | 方块贴图 | 模组方块可能变品红 |
| 可选 | ffmpeg | 动画只出帧序列，转视频要自己来 |

**缺可选的不会被拦**，只是少相应功能 —— 所以**你也可以先什么都不装，直接出风景图试试**。

## 第 6 步：出第一张封面

### 6.1 先扫一下，看哪里好看

```bash
python py/cli.py scan "D:/saves/我的世界" --area -2100,-1600,-1400,-900
```

`--area` 是**允许搜索的矩形范围**，格式是 `x0,x1,z0,z1`。

**不知道自己的坐标怎么办**：

1. 进游戏，按 **F3**，左上角能看到 `XYZ: -1838 / 65 / -1108`
2. 把 X 和 Z 各加减 250，就是你的 `--area`
   （上面这个例子就是 `-2100,-1600,-1400,-900`）

输出：

```
推荐机位 8 个（开阔度 / 坐标 / 地面Y / 方位角 / 平坦格数）:
  开阔度1.00  (-2036,-1016) Y=64  az=  0°  平坦 961
  开阔度1.00  (-2022,-1024) Y=64  az=  0°  平坦 961
  ...
```

| 列 | 含义 |
|---|---|
| **开阔度** | 1.00 = 视线方向上没有东西挡着 |
| **坐标** | 站的位置（MC 坐标） |
| **地面Y** | 那一格的地面高度 |
| **方位角** | 相机朝哪看（MC 角度） |
| **平坦格数** | 周围有多少格同高度的平地（961 = 31×31） |

### 6.3 表情与姿势（可选）

给角色加表情，或者换成「双手在胸前比取景框」的照相姿势：

```bash
python py/cli.py shoot "<存档>" --area x0,x1,z0,z1 --out ./出图 --pose snapshot --face happy
```

| 参数 | 可选值 | 说明 |
|---|---|---|
| `--pose` | `action`（默认）/ `hero` / `raise` / `guard` / `snapshot` / `run` / `jump` / `point` / `wave` / `sit` / `legacy` | `snapshot` = 照相取景框；`run` 跑动 / `jump` 跳跃 / `point` 指向 / `wave` 挥手 / `sit` 坐地 |
| `--face` | `auto`（默认）/ `happy` / `angry` / `sad` / `surprised` / `curious` / `neutral` / `blink` / `0` | `auto` 只在 `--pose snapshot` 时笑；`0` 保留旧皮肤眼 |
| `--skin3d` | 开关 | 头部外层（头发/帽子）按皮肤像素挤出厚度；身体外层加一层衣料厚度。默认关 |
| `--skin3d-thick` | `0.02` | 3D 皮肤厚度（格），范围 0.005–0.06 |

表情会临时启用 BPS 的 **3D 五官**：眉毛、眼皮、瞳孔、嘴一起动；同时把皮肤上画的眼睛/眉毛/嘴盖成肤色，避免双眼睛。瞳孔颜色会从皮肤采样（找不到冷色瞳孔时保留 BPS 默认紫瞳）。

`--face 0` 完全走旧路线，保留皮肤贴图眼睛；`--face neutral` 是「3D 五官的平静脸」，不是旧皮肤眼。

想让人物更立体，加 `--skin3d`：头发/帽子会按皮肤的不透明像素挤出真实厚度，衣服外层加一层衣料厚度；脸仍然保留皮肤贴图，不会变成 3D 净脸。厚度用 `--skin3d-thick` 调：

```bash
# 跑动 + 3D 头发 + 自然皮肤脸（静态封面推荐）
python py/cli.py shoot "<存档>" --area x0,x1,z0,z1 --out ./出图 \
  --pose run --face 0 --skin3d --dist 11
```

> 3D 皮肤只处理头部和身体外层；它不会改变 BPS 的方块比例。要更高精度的模型，需要换一套 rig。

几个常用组合：

```bash
# 微笑标准照
--pose snapshot --face happy

# 生气皱眉
--face angry

# 惊讶 O 嘴
--face surprised

# 单侧嘴角上扬的坏笑
--face curious

# 眨眼（单帧封面用；动画里可做闭眼）
--face blink

# 跑动 / 跳跃 / 挥手 / 指向 / 倚靠
--pose run
--pose jump
--pose wave
--pose point

# 完全不改表情（旧行为）
--face 0
```

在 DSH 工具里对应 `mc_shoot` 的 `pose` / `face` 参数；也可以直接设环境变量
`DSH_FACE=happy`、`DSH_POSE=snapshot`。表情强度用 `DSH_SMILE_SCALE` 调
（0.6 含蓄、1.0 默认、1.3 夸张）。3D 皮肤也可以用环境变量
`DSH_SKIN3D=1`、`DSH_SKIN3D_THICK=0.02`。

### 6.4 把存档装成背景地图（可选）

不想只出一张封面，而是想把整片地形装进 Blender 当**可编辑背景**，用：

```bash
python py/cli.py map-import --save "<存档>" \
  --area -2100,-1600,-1400,-900 --center -2016,-1197 \
  --radius 64 --y 0,160 --out ./背景地图 --res 1280x720
```

也可以直接给地图库里已经上传过的地图 id：

```bash
python py/cli.py map-import --map m_855616fd35fa --out ./背景地图
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--save` / `--map` | —（二选一必填） | 存档目录 / 地图库 id |
| `--area` | 自动 | `x0,x1,z0,z1`；不填就按 region 主簇 + 出生点自动选 |
| `--center` | area 中心 | 导出半径的中心 `x,z` |
| `--radius` | 96 | 半径（格）。64 适合一个村庄，96–128 适合大场景 |
| `--y` | 0,320 | 导出高度范围；山地/洞穴被削时调大 |
| `--out` | 必填 | 输出目录 |
| `--name` | 背景_世界 | `.blend` 文件名 |
| `--res` / `--samples` | 1280x720 / 64 | 预览图尺寸 / EEVEE 采样 |
| `--no-preview` | 关 | 不渲预览，只出工程 |
| `--force` | 关 | 忽略导出缓存，重新解析地形 |

产物在 `--out` 下：

```
背景_世界.blend      ← 用 Blender 打开就能继续编辑
预览.png             ← 自动机位的预览图
导入信息.json        ← 对象/面数/材质/MCprep 状态/范围
世界.obj / 世界.mtl  ← 中间地形
_export_cache.json   ← 导出缓存（同参数第二次会秒过）
```

工程里固定三个集合：

- `MAP`：地形 + 兜底地面（可以直接往里加自己的建筑/道具）
- `LIGHTS`：太阳 + 补光
- `CAMERA`：自动机位（可以换成自己的相机）

**材质**：本机装了 MCprep 就自动调它的 `prep_materials`；没装、或 MCprep 注册失败
（例如 tracker 文件没写权限），会自动退回内置的「贴图 + 群系乘色 + 调平粗糙度」，
不会因为缺 MCprep 就失败。

**缓存**：同一存档、同一区域/半径/Y 范围/贴图，第二次会直接复用 `世界.obj`；
改了其中一个参数才重导。想强制重导加 `--force`。

**原创说明**：工作流参考 MCprep / Mineways / MiBlend / MCBlend 的公开做法
（OBJ 世界导入 → 准备材质 → 归入 MAP 集合）；本项目的存档解析、区域计算、导出、
缓存、场景组织是原创实现，不分发也不依赖这些插件，详见 `THIRD_PARTY_NOTICES.md`。

在 DSH 工具里对应 `mc_map_import`，参数同名：
`save` / `map` / `area` / `center` / `radius` / `y` / `out` / `name` / `res` / `samples` / `preview` / `force`。

## 看懂审图结果

每次渲完都会自动审图。输出长这样：

```
    审图: WARN 62 分
      ⚠️  [1] 看到的是【背面】（头部皮肤占比仅 8.9%）—— 角色朝向要转过来
      ⚠️  [2] 接地可疑（色差 25.7）
    🔧 角色朝向 -125.0° → 55.0°（转正面）
```

### 三种结论

| 结论 | 分数 | 意思 |
|---|---|---|
| **PASS** | ≥ 80 | 没问题，可以直接用 |
| **WARN** | 60–79 | 有小毛病，能用但建议改 |
| **FAIL** | < 60 | 明显有问题，会自动重渲 |

### 各项检查在查什么

| 提示 | 什么意思 | 自动怎么改 |
|---|---|---|
| `看到的是【背面】` | 角色背对镜头。判据是**头部区域的皮肤色占比**——正面能看到脸（~30%），背面只有头发（~9%） | yaw +180° |
| `疑似【脚没踩地】` | 脚底下方那块的颜色和旁边地面差太多 | 加大 `--sink` |
| `过曝：x% 的像素接近死白` | 天空把画面撑爆了 | 降低天空强度 |
| `看不出布光` | 角色周围地面太均匀 = 平光 | 抬高灯光倍率 |
| `主体太小` | 角色占画面高度不到 14% | 拉近相机 |

### 自动重渲

如果没达标，它会**自己改参数再渲一遍**，最多 3 轮（`--attempts`）：

```
第 1 次 → WARN 62 → 🔧 转正面
第 2 次 → PASS 92 → ✅ 停
```

**只有"能自动修的"才会自动修**。像"背景全是建筑"这种它就修不了（那属于选错机位），
会保留问题列表让你自己决定。

### 人工看图（标注版）

审图还会输出一张**画了框的图**到 `./出图/审图/`，方便你确认它框对地方了：

- 红框 = 它识别出的角色位置
- 左上角 = 结论和分数

动画要在**封面工程**上做。上面出的图旁边就有 `.blend` 文件：

python py/cli.py anim "./出图/尝试1/封面_世界.blend" --out ./动画

### ⚠️ 先只渲几帧验证动作

完整 240 帧要 5–6 分钟。**先用 `--preview` 渲几张关键帧**，确认动作方向对了再跑全片：

```bash
python py/cli.py anim "./出图/尝试1/封面_世界.blend" --out ./动画 --preview 1,40,60,75,130,155
```

会把这几帧渲染成 `preview_0001.png` 这样。拼成一张对比图看：

```bash
ffmpeg -i preview_0001.png -i preview_0040.png -i preview_0060.png \
       -filter_complex hstack=inputs=3 预览.png
```

### 确认没问题后跑全片

```bash
python py/cli.py anim "./出图/尝试1/封面_世界.blend" --out ./动画
```

### 转成 MP4 / GIF

```bash
cd 动画
ffmpeg -framerate 24 -i frame_%04d.png -c:v libx264 -crf 18 \
       -pix_fmt yuv420p -movflags +faststart 动画.mp4
```

参数解释：
- `yuv420p` —— 兼容性最好，B 站/剪辑软件都认
- `+faststart` —— 让视频能边下边播
- `-crf 18` —— 画质，数字越小越清晰（18 基本无损，23 是默认）

**做 GIF**（注意 GIF 会比 MP4 大 3–4 倍，建议只做 3–5 秒）：

```bash
ffmpeg -framerate 24 -i frame_%04d.png -vf "fps=12,scale=480:-1:flags=neighbor,split[a][b];[a]palettegen=max_colors=128[p];[b][p]paletteuse" 动画.gif
```

### 默认动画是什么

「**杀戮光环**」：角色挥剑两刀 + 周围旋转的发光能量环 + 斩击弧光，10 秒 / 240 帧 / 24fps。

时间轴：

| 帧 | 动作 |
|---|---|
| 1–36 | 待机，光环慢转 |
| 36–52 | 第一刀蓄力（手臂抬起后拉） |
| **52–60** | **挥砍** ← 斩击弧光炸开 |
| 60–92 | 收招回中 |
| 128–150 | 第二刀（反手） |
| 170–240 | 归位 |

### 做一段走路 / 跑步（不用写代码）

封面工程默认是"飞天"片子的底子，但走路跑步已经打包好了：

```bash
python py/cli.py anim "./出图/尝试1/封面_世界.blend" --preset walk --out ./动画_走路 --preview 1,9,17,25
python py/cli.py anim "./出图/尝试1/封面_世界.blend" --preset run  --out ./动画_跑步 --preview 1,6,11,16
```

| 预设 | 循环 | 总帧数 | 时长 @24fps |
|---|---|---|---|
| `walk` | 32 帧 × 4 | 128 | 5.3 秒 |
| `run` | 20 帧 × 4 | 80 | 3.3 秒 |

这两个预设自带一整套"贴地拍摄"的处理，你不需要再管：

- **清地形**：封面工程里地形有 246 格宽，角色一贴地就被土挡死 → 自动隐藏，另铺一块棋盘地面
- **脱装备**：头盔 / 胸甲 / 手里的剑都是挂在骨头上的独立对象 → 自动藏掉，不然走路还举着剑
- **关 IK**：BPS 骨架的腿默认是 IK 模式，这时候转 FK 骨骼**完全没反应** → 自动切回 FK
- **接触帧线性**：不设线性，Blender 的默认缓动会把脚"拖回来" → 自动设
- **末帧闭环**：复制循环时最后一帧容易漏键，渲染出来会抽一下 → 自动补

**脚打滑**的话调 `walk.json` 里的 `motion.speed`：

```jsonc
"motion": {"type": "ground", "speed": 0.0705, ...}   // 世界单位/帧
```

量法：量出一个循环里接触脚相对身体往后走的距离 `D`，`speed = D ÷ 循环帧数`。
注意 `Root.location` 的 1 个单位 ≠ 1 世界单位（这台 rig 上是 0.625），别拿骨骼数值直接当世界单位。

## 第 7.5 步：一句话出短片

0.6.0 起 `anim` / `film` 都能直接吃中文提示词：说几秒、什么动作、什么机位，自动选预设并排时间轴。

### 单段长镜头：`anim --prompt`

```bash
python py/cli.py anim "./出图/尝试1/封面_世界.blend" \
  --prompt "10秒跑步，低机位，跟拍" --out ./动画_跑步
```

- **秒数**：说「10秒」就出 10 秒。循环动作（跑/走）会自动补循环遍数，非循环动作
  （御剑/施法）会把整条时间轴重定时，日志会出现 `[8] 重定时：240 帧 → 120 帧`。
- **画幅**：提示词里写「9:16」出竖屏，写「16:9」或不说就横屏。
- **机位词**：低机位 / 跟拍 / 仰拍 / 平视 / 一镜到底。
- **动作词**：跑、走、御剑、施法、冲刺、骑、超人、杀戮光环。

> `--frames` 只是兜底默认值（240）；提示词里的秒数优先。不确定动作对不对，先加
> `--preview 1,24,48` 只渲几帧。

### 多镜头：`film --prompt`

```bash
python py/cli.py film --blend "./出图/尝试1/封面_世界.blend" \
  --prompt "5秒跑步，低机位，跟拍" --out ./短片 --animatic
```

- 自动切 3 镜（建立 / 中景 / 近景），三镜方位角分别 +25° / 0° / −20°；
- 输出 `xxx.mp4` + `分镜表.md`，`--animatic` 是 480×270 低清样片，只看节奏；
- 去掉 `--animatic` 就按分镜表的分辨率出正式版（提示词自动分镜默认 1280×720）；
  想换分辨率/采样，把自动生成的 `分镜表.md` 旁 JSON 改 `res` / `samples` 后用 `--plan` 重跑。

### 时长与预设

| 预设 | 基础时长 | 适用 |
|---|---|---|
| `run` / `walk` | 80 / 128 帧（3.3 / 5.3 秒） | 跑、走；请求更长会自动补循环 |
| `yujian` | 240 帧（10 秒） | 御剑飞天；请求更短会整条重定时 |
| `killaura`（默认） | 240 帧 | 挥剑 + 光环 |
| `conduct` / `dash` / `ride` / `superman` / `dl01–03` | 120–240 帧 | 施法 / 冲刺 / 骑乘 / 腾空 / 分镜 |

配方本身写死时长是历史行为；现在 `--frames` / 提示词秒数优先，配方只决定动作形状。

### 保留真实地图时，光会变

提示词短片默认 `DSH_ANIM_KEEP_WORLD=1`（保留存档地形）。这时会同时开
`DSH_ANIM_NATURAL_LIGHT=1`，关掉摄影棚的 AREA/POINT/SPOT，只留太阳和天空，
避免雪地上出现一圈假光斑。想强制用摄影棚灯：

```bash
DSH_ANIM_NATURAL_LIGHT=0 python py/cli.py anim ... --prompt "2秒跑步"
```

自然光下画面会偏平，这是下一步要补的配光（太阳角度 / 天空强度 / 冷暖对比）。

### 让相机沿路径飞

```bash
python py/cli.py camera-path "<存档world目录>" --area -64,64,-64,64 \
  --start 13,-59 --goal 13,-45 --out path.json
```

分镜表里加 `"camera_path": "path.json"`。路径没有 `look_at` 时，相机会逐帧对准
角色头部（不再沿路径切线看，所以不会第一帧就飞上天）。路径起点别正好放在角色脚下。

## 调整参数：什么情况调什么

### 「角色背对镜头 / 看不出是正脸」

```bash
--yaw 25      # 默认值，3/4 侧脸面向镜头
--yaw 55      # 更正对镜头
--yaw -35     # 转向另一边
```

> 原理：相机在角色的 **-Y 方向**，所以 `yaw=25°` 时角色刚好侧脸对着相机。

### 「画面太亮 / 一片白」

```bash
--sky 0.02                    # 默认 0.03，往下调
--view-transform Filmic      # 或换成有高光压缩的
```

> ⚠️ **这里有个反直觉的点**：用「标准」视图转换时，天空强度**必须压到 0.05 以下**。
> 因为「标准」没有高光压缩，而物理天空输出的是辐射度量 —— 强度一高就直接削顶成白，
> 整个动态范围被天空占满，三点布光完全显不出来（表现就是"背景死白 + 没有光源"）。

### 「草地是灰白的 / 地面一片惨白」

不是参数问题，是 **MCprep 没跑起来**：MC 的草顶贴图本身是灰的，颜色靠群系 tint。
MCprep 正常时会帮你染色；它没注册上（常见于写 tracker 文件被拒）时，草就一直是灰白。

现在的版本会**自动兜底**：日志里出现这行就说明走了内置染色，图不会发白：

```
⚠️ MCprep 没跑通 → 用内置兜底：贴图 + 群系染色 + 调平材质
```

想彻底修好，去看 `python py/cli.py doctor` 里 MCprep 那一项，或者重装 MCprep 附件。
兜底染色的草色是可调的（`build_cover.py` 里的 `BIOME_TINT`），但通常不用动。

### 「出一张图太慢 / 想快点看效果」

```bash
--samples 32          # 正式档采样，默认 48（越低越快、颗粒越多）
--vol-samples 16      # 体积雾采样，默认 32；`0` 等于关雾
--attempts 1          # 试渲轮数，默认 2
--backdrop clean      # 只要干净背景（不导出地形，补一块草地平面）
```
> 0.6.1 起默认就是「试渲 960×540/16 → 定稿 1920×1080/48」两段式，
> 同一台机器实测 111s → 38.6s（Vulkan 后端）。想退回 OpenGL 用
> `DSH_GPU_BACKEND=none`，速度会掉回 60s 左右但兼容性最好。

### 「背景里有别的建筑 / 多余方块」

```bash
--backdrop clean      # 藏掉导出的地形，补 600×600 草地平面（棚拍感，草地保留原版贴图）
--backdrop studio     # 同上，但更平、更适合抠图
```
> 默认仍是 `world`（用真实地图，最自然）。clean/studio 只在自定义布景、
> 抠图、或者存档里有半截建筑时用。**整块地形进画面是半径 44 导出的**，
> 想保留地图又要干净，只能靠选点（`--center` 挪到开阔处）。

### 「两个角色的腿粘成一根柱子」

0.6.1 起站姿自动走 IK 岔腿（`Top Leg` 切 `FK<->IK`、脚目标外移 0.15 格、前后错开 0.1 格）：

```bash
-DSH_STANCE=0         # 关掉，回到并腿站姿
-DSH_STANCE_X=0.25    # 左右外移更多，八字更明显
-DSH_STANCE_FWD=0.2   # 前后错开更多，更像迈步
```
> 纯 FK 调不出来：这台 rig 的腿只有 X 轴（前后）有效，Y/Z 都是沿骨长扭转。

### 「角色看着像飘在空中」

```bash
--sink 0.12     # 默认 0.06，加大让脚陷得更深
```

### 「剑握得不对 / 想换持剑姿势」

封面默认会把右臂摆成**举剑**姿势（FK：肩 -40°/肘 -85°/腕 6°），剑柄落在 `Hand.R` 手骨上。
手感不对时用环境变量微调，不用改代码：

```bash
$env:DSH_ARM_POSE = "0"                    # 关掉摆姿势，保持默认垂手站姿
$env:DSH_ARM_SHOULDER = "-55,0,30"         # 肩：前后 / 扭转 / 外张（度）
$env:DSH_ARM_ELBOW = "-95,0,0"             # 肘
$env:DSH_ARM_WRIST = "0,0,10"              # 腕
$env:DSH_SWORD_SINK = "0.55"               # 剑往掌心沉多少（本地单位）；0 = 柄尾顶在掌心
```

> 握持的判据不是"手在剑旁边"，而是**剑有一段在手掌内部**：
> 柄尾从拳下露出、刀刃从拳上伸出。`DSH_SWORD_SINK` 调的就是这个"咬合深度"，
> 0 会变成"托着"，0.8 以上柄会插进手臂。

> 原理：BPS V4 的手臂默认是 **FK**（IK 影响为 0），摆姿势就是转 `Top Arm.R` /
> `Bottom Arm.R` / `Hand.R` 三根 pose bone；"剑握在手里"= 把剑绑到 `Hand.R`，
> 再把抓握点取在手骨上（网格 bbox 不含骨架形变，别用它算位置）。

> MC 方块边缘很锐利，**哪怕只离地 0.019 格，看起来也像悬浮**。所以默认就沉了 0.06。

### 「背景全是建筑，不好看」

这不是参数问题，是**机位问题**。换一个：

```bash
python py/cli.py scan <存档> --area <你的范围> --top 10
# 换一个开阔度高的坐标
python py/cli.py shoot <存档> --area <你的范围> --out ./出图 --center <新坐标>
```

也可以直接换方位角，让背景朝向开阔的一侧：

```bash
--cam-az 200     # MC 角度。0=+x 90=+z 180=-x 270=-z
```

### 「角色太小 / 太大」

```bash
--dist 8        # 默认 11.2，调小 = 角色更大
```

### 「审图总是不过，想宽松点」

```bash
--target 70         # 默认 85，降低目标分
--attempts 5        # 默认 3，多试几轮
```

## 出问题了怎么办

### 1. 先跑 doctor

```bash
python py/cli.py doctor
```

**90% 的问题这里能看出原因**，而且会给出安装指引。

### 2. 看日志

`shoot` 会在输出目录写几个日志文件：

| 文件 | 内容 |
|---|---|
| `_export.log` | 导出几何 |
| `_build.log` | 搭 Blender 场景 |
| `_render.log` | 渲染 |
| `结果.json` | 每轮审图的完整结果和参数 |

### 3. 常见现象

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 草地是灰白的 | MCprep 没装/没启用 | 跑 `doctor`，按指引装 |
| 模组方块变成品红 | 缺贴图 | 装方块贴图目录 |
| 画面里没有角色 | 没装 BPS 骨架 | 跑 `setup` 装配；或就用风景图 |
| 角色空手 | 没装物品库 | 跑 `setup` 装配 |
| `这个区域里没找到合适的开阔平地` | 扫描范围内没有成片草地 | 换 `--area`，或把 `--radius` 调小 |
| 渲染很慢 | 采样数高 | 见下 |

### 4. 想让渲染快一点

默认是 EEVEE + 256 采样 + 1280×720，一张约 10 秒。
如果要快速试参数，改小一点（在 `封面_世界.blend` 里，或者等后续版本开放参数）。

## 术语表

| 词 | 意思 |
|---|---|
| **存档 / save** | Minecraft 世界数据目录，含 `region/` 文件夹 |
| **机位** | 相机的位置和朝向 |
| **方位角 / az** | 相机朝哪看。MC 角度：0°=+x 方向，90°=+z，180°=-x，270°=-z |
| **开阔度** | 视线方向上没被挡的比例，1.00 = 完全开阔 |
| **审图** | 用 OpenCV 自动检查渲染结果（朝向/接地/曝光/布光/构图） |
| **审图闭环** | 审图不达标 → 自动改参数 → 重渲，循环到达标或用完轮数 |
| **装配 / setup** | 从你本地的资源目录把第三方资产（骨架、MCprep）搬到插件里 |
| **vendor/** | 装配产物存放处。已在 `.gitignore` 里，不会进版本库 |
| **yaw** | 角色自身的朝向（不是相机的） |
| **sink** | 让脚陷进地面的深度，防止"看起来悬浮" |
| **视图转换** | Blender 的色彩映射方式。`Standard` 直出/无压缩，`Filmic`/`AgX` 有高光压缩 |
| **生物群系染色** | MC 的草和树叶贴图本身是灰度的，绿色是运行时按生物群系乘上去的 |
| **Anvil** | Minecraft Java 版的存档格式（`.mca` 区域文件） |
