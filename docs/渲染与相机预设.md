# 渲染与相机预设

> 两个**纯新增**模块，不改动 `anim_kit.py` / `cli.py` / `pipeline.py`：
>
> | 文件 | 负责 | 依赖 |
> |---|---|---|
> | `py/render_presets.py` | 渲染规格：缩略图 / B 站直出 / Cycles 高品质 / 草稿，外加引擎与性能开关 | 标准库 + `bpy` |
> | `py/blender/camera_kit.py` | 相机能力：抖动 / 360° 环绕 / 镜头切换 / 天空延时 | 标准库 + `bpy` + `mathutils` |
>
> 两个模块都是「传入 scene，写完把**实际生效**的值读回来给你」。所以既能当
> 一次性开关用，也能把返回值塞进报告、做断言、写日志。
>
> 所有配置项都容错：属性在本版本不存在 → 打印一行
> `[render] 跳过 xxx（这个版本没有）` / `[camera] 跳过 xxx（…）` → 继续，
> **绝不抛异常中断渲染**。唯一会抛的是「名字写错」和「scene 传 None」——那是
> 调用方的 bug，静默吞掉只会让人对着没生效的画面发呆。

## 一、渲染预设 `py/render_presets.py`

### 1. 三行上手

```python
import sys, bpy
sys.path.insert(0, r'E:\游戏与自媒体\AI自媒体工作区\04_工具脚本\dsh-blender-mc\py')
import render_presets as rp

eff = rp.apply_preset(bpy.context.scene, 'thumbnail')   # 返回实际生效的参数
print(eff['lens'], eff['res'], eff['engine'])           # 80.0  1280x720  BLENDER_EEVEE
```

`apply_preset(scene, name, spec=None)`

| 参数 | 说明 |
|---|---|
| `scene` | `bpy.context.scene`，传 `None` 抛 `ValueError` |
| `name` | 预设名，或别名（见下表）；写错抛 `ValueError`，报错里会列出可选项 |
| `spec` | 覆盖 dict；**值为 `None` 表示「这一项不动」**，不认识的键打一行日志后忽略 |

### 2. 四个预设总表

| 预设 | 别名 | 引擎 | 分辨率 | 采样 | 一句话用途 |
|---|---|---|---|---|---|
| `thumbnail` | `thumb` / `缩略图` | EEVEE | 1280×720 | 64 | 封面/缩略图静帧：透明背景 + 80mm + 三点光 + AgX Punchy |
| `bilibili` | `bili` / `b站` / `video` | EEVEE | 1920×1080 | 32 | B 站投稿视频直出，带 0.35 运动模糊 |
| `cycles_hq` | `cycles` / `hq` | CYCLES | 1920×1080 | 128 | 高品质静帧：降噪 + 自适应 + 噪点阈值 0.01 |
| `quick` | `draft` / `fast` / `preview` / `草稿` | EEVEE | 960×540 | 8 | 调机位/试动作：关运动模糊、关景深 |

### 3. 每个预设的完整参数

**`thumbnail`** —— 缩略图。一次一张，要快、要干净，直接出带 alpha 的 PNG 贴封面版式。

| 键 | 默认值 | 单位 | 说明 / 适用场景 |
|---|---|---|---|
| `engine` | `EEVEE` | — | 静帧够用且秒出 |
| `res` | `1280x720` | px | 封面版式里 720p 已足够 |
| `samples` | `64` | 采样数 | EEVEE TAA，静帧 64 无可见噪点 |
| `exposure` | `0.0` | EV | 不额外推曝光，靠灯光 |
| `view_transform` | `AgX` | — | 4.x/5.x 都在；不在就依次降级 Filmic→Standard |
| `look` | `AgX - Punchy` | — | 提高对比与饱和，缩略图更抓眼 |
| `motion_blur` | `0.0` | 快门角 | 静帧不要动态模糊 |
| `vector_blur` | `False` | — | 见 §5 版本坑 |
| `film_transparent` | `True` | — | 透明背景；开启时自动把 `image_settings.color_mode` 设成 `RGBA` |
| `lens` | `80` | mm | 长焦压缩透视，人物比例更像海报 |
| `lights` | `{'key':100, 'fill':60, 'rim_rx':-90}` | W / 度 | 三点光，rim 转到正后方；`fill` 给 50~70 都稳 |

**`bilibili`** —— 视频直出，和 `presets/walk.json` / `ride.json` 的 `render` 段同规格。

| 键 | 默认值 | 单位 | 说明 |
|---|---|---|---|
| `engine` | `EEVEE` | — | 1080p 逐帧，EEVEE 才现实 |
| `res` | `1920x1080` | px | B 站推荐 |
| `samples` | `32` | 采样数 | 动起来后 32 足够，噪点被运动模糊糊掉 |
| `motion_blur` | `0.35` | 快门角 | 关键：没有它 24fps 的动作会「顿」 |
| `film_transparent` | `False` | — | 视频要实背景 |
| `view_transform` / `look` | `AgX` / `AgX - Punchy` | — | 与缩略图同一条色彩管线 |

**`cycles_hq`** —— 高品质静帧。

| 键 | 默认值 | 单位 | 说明 |
|---|---|---|---|
| `engine` | `CYCLES` | — | 真 GI，写实皮肤/盔甲反射 |
| `res` | `1920x1080` | px | — |
| `samples` | `128` | 采样数 | 配合自适应，实际耗时远低于固定 128 |
| `denoise` | `True` | — | → `cycles.use_denoising` |
| `adaptive` | `True` | — | → `cycles.use_adaptive_sampling` |
| `noise_threshold` | `0.01` | 噪声阈值 | → `cycles.adaptive_threshold` |
| `motion_blur` | `0.0` | 快门角 | 单帧不需要 |
| `gpu` | *不设* | — | **故意留空**：切 GPU 改的是用户偏好，不该被预设擅自动，要就显式传 |

**`quick`** —— 草稿。

| 键 | 默认值 | 单位 | 说明 |
|---|---|---|---|
| `res` | `960x540` | px | 半分辨率 |
| `samples` | `8` | 采样数 | 看构图够用 |
| `motion_blur` | `0.0` | 快门角 | 关掉省一半时间 |
| `dof` | `False` | — | 关景深，先看清动作 |
| `view_transform` | `AgX` | — | 和成片同一条色彩管线，草稿才对得上色 |

### 4. `spec` 覆盖用的规范键

`spec` 和预设内部用的是**同一套键**（`rp.KNOWN_KEYS`）：

| 键 | 写入的属性 | 单位 / 取值 |
|---|---|---|
| `engine` | `scene.render.engine` | `'EEVEE'` / `'CYCLES'`（内部自动探测真实枚举名） |
| `res` | `render.resolution_x/y` + `resolution_percentage=100` | `'1280x720'`，`×` 和空格也认 |
| `samples` | EEVEE→`eevee.taa_render_samples`；Cycles→`cycles.samples` | 整数 |
| `exposure` | `view_settings.exposure` | EV |
| `motion_blur` | `render.use_motion_blur` + `motion_blur_shutter` + `motion_blur_position='CENTER'` + `eevee.motion_blur_steps=2` | 快门角，`0` = 关 |
| `vector_blur` | 优先 `eevee.use_vector_blur`，没有就退回 `render.use_motion_blur` | bool |
| `film_transparent` | `render.film_transparent`（开则 `color_mode='RGBA'`） | bool |
| `view_transform` | `view_settings.view_transform` | `AgX` / `Filmic` / `Standard` … |
| `look` | `view_settings.look` | `AgX - Punchy`；`'auto'` = 按当前变换自动挑；对不上退回 `'None'` |
| `lens` | `scene.camera.data.lens` | mm |
| `dof` | `scene.camera.data.dof.use_dof` | bool |
| `gpu` | `cycles.device` + `prefs.compute_device_type` + 逐个 `prefs.devices[].use` | bool（见 §5 注意） |
| `simplify` | `render.use_simplify` | bool |
| `simplify_threshold` | `render.simplify_subdivision_render` | 整数，渲染时细分上限 |
| `noise_threshold` | `cycles.adaptive_threshold` | 0~1，越小越干净越慢 |
| `denoise` | `cycles.use_denoising` | bool |
| `adaptive` | `cycles.use_adaptive_sampling` | bool |
| `lights` | 三点光（见 §6） | dict |

```python
# 只改一部分，其余照预设
rp.apply_preset(sc, 'quick', {'lens': 35, 'samples': 12, 'res': '640x360'})
# 只切引擎
rp.apply_preset(sc, 'quick', {'engine': 'CYCLES'})
# 什么都不动某一项
rp.apply_preset(sc, 'thumbnail', {'film_transparent': None})
```

### 5. 引擎与性能开关（重点：都容错）

| 键 | 目标属性 | 备注 |
|---|---|---|
| `engine` | `scene.render.engine` | **不硬编码**。`probe_engines()` 先读静态枚举，再故意赋一个非法值、从 `enum "x" not found in (...)` 里把真实列表正则抠出来 —— 因为 Cycles 是 addon 注册的，静态枚举里根本看不到 |
| `simplify` | `scene.render.use_simplify` | 草稿期关掉细分/毛发，省一半以上时间 |
| `simplify_threshold` | `scene.render.simplify_subdivision_render` | 只有 `simplify=True` 才写 |
| `gpu` | `scene.cycles.device`（`'GPU'`/`'CPU'`） | `True` 时先挑后端（有 N 卡优先 `OPTIX`，其次 `CUDA`，再 `HIP`/`ONEAPI`/`METAL`），`prefs.get_devices()` 后只开非 CPU 设备；一台卡都没有就打一行提示落回 CPU |
| `noise_threshold` | `scene.cycles.adaptive_threshold` | 没这个属性就跳过 + 提示 |
| `vector_blur` | 自动探测 | 见下 |

**`vector_blur` 的真实情况**：EEVEE Next（4.2+）**没有**独立的矢量模糊开关，5.2 的
`scene.eevee` 里既没有 `use_vector_blur` 也没有 `use_bloom` / `use_gtao`。所以传
`vector_blur=True` 时会打一行

```
[render] 本版本无独立矢量模糊开关，已用 render.use_motion_blur 顶替
```

并把 `render.use_motion_blur` 打开 —— 效果上矢量模糊本就是运动模糊的一种，
要精确控制就用 `motion_blur` 快门角。传 `False` 时只提示、不写任何东西。

**`gpu=True` 的副作用要说清**：它改的是**用户偏好**
（`preferences.addons['cycles'].preferences`），不只这个 `.blend`。所以
`cycles_hq` 预设里故意**不设** `gpu`，必须显式传才生效。想恢复：

```python
rp.apply_preset(sc, 'cycles_hq', {'gpu': False})     # cycles.device → CPU
```

### 6. 三点光怎么认灯

`three_point_lights(scene, cfg)` 靠**灯名**匹配角色：

1. 名字按 `[._\-\s]` 切词，整词或前缀命中 `key` / `fill` / `rim`（也认 `back`、`轮廓`、`背光`）；
2. 例：`Key.001` → `['key','001']` 命中 key；`Fill` 命中 fill；`Rim` 命中 rim；
   **`SunKey` → `['sunkey']` 不算 key 灯**（避免把太阳当三点光的主灯改能量）；
3. `rim` 默认转到 `rotation_euler.x = -90°`（`rim_rx`），即从正后方往相机方向补轮廓；
4. 没匹配上任何灯也不抛异常，只在返回值里留 `found: []`。

`cfg` 结构：

```python
{'key': 100.0, 'fill': 60.0, 'rim': None, 'rim_rx': -90.0,
 'size': {'key': 4.0},                    # 柔光箱尺寸（米）
 'color': {'fill': [0.88, 0.93, 1.0]}}    # 偏冷补光
```

`apply_preset` 返回「写完读回来」的 dict：

### 9. 版本兼容表（Blender 5.2.3 LTS 实测）

| 现象 | 真相 | 模块怎么处理 |
|---|---|---|
| `enum_items` 里只有 `BLENDER_EEVEE` | Cycles 是 addon 注册的，静态枚举看不到；真实可赋值 `('BLENDER_EEVEE','BLENDER_WORKBENCH','CYCLES')` | 赋非法值套报错列表 |
| `BLENDER_EEVEE_NEXT` 报 `TypeError: enum ... not found` | 4.2~4.5 才叫 `_NEXT`，5.2 改回 `BLENDER_EEVEE` | 候选表里两个都试 |
| `scene.eevee.use_vector_blur` 不存在 | EEVEE Next 没有独立开关 | 退化成 `render.use_motion_blur` + 提示 |

| `view_settings.look = 'NONE'` 报错 | 「无」在 5.x 叫 `'None'` | 候选 `(look, 'None', 'NONE')` 逐个试 |
| `render.file_format` 不存在 | 在 `render.image_settings.file_format` | 本模块用 `image_settings` 路径 |
| 运动模糊不在 `eevee` 下 | `render.use_motion_blur` + `eevee.motion_blur_steps` | 按此写 |

## 二、相机能力 `py/blender/camera_kit.py`

### 1. 注册表与调用方式

```python
import sys, bpy
sys.path.insert(0, r'E:\游戏与自媒体\AI自媒体工作区\04_工具脚本\dsh-blender-mc\py\blender')
import camera_kit as ck

sc, cam = bpy.context.scene, bpy.context.scene.camera
ctx = {'base': (0, 0, 0), 'total': 240, 'fps': 24}   # anim_kit.scene_ctx() 的子集，缺了也能跑

ck.CAM_OPS['shake'](sc, cam, ctx, {'strength': 0.02, 'scale': 8})
ck.apply_cam_op(sc, cam, ctx, 'orbit', {'sweep': 360})
ck.apply_cam_ops(sc, cam, ctx, [                      # 批量 + 别名
    {'op': 'noise', 'strength': 0.01},
    {'op': 'sky', 'hours': [[1, 8], [96, 20]]},
])
```

四个能力签名统一 `def xxx(scene, cam, ctx, spec)`：

| 名字 | 函数 | 别名 | 课程 | 干的事 |
|---|---|---|---|---|
| `shake` | `shake` | `noise` / `jitter` / `抖动` | T27 | 相机 F-Curve 挂 Noise 修改器 → 手持/冲击抖动 |
| `orbit` | `orbit` | `turntable` / `环绕` | T38 | 空物体当父级，相机绕角色转，360° 环绕 |
| `cuts` | `cuts` | `cut` / `切换` | T33 | 时间线 marker + `cam_cut_1..n` 多机位切换 |
| `sky_timelapse` | `sky_timelapse` | `sky` / `timelapse` / `延时` | T50 | World 强度 + 太阳高度按时间打关键帧 |

`apply_cam_op(...)` 名字写错会抛 `ValueError` 并列出可选项。
返回值里 `applied` 表示是否真生效，`skipped` 是本次跳过的原因清单。

`ctx` 只用到两个键：`base`（角色世界坐标，决定环绕圆心/瞄准点）和 `total`（总帧数，
决定时间轴；缺了退化成 `scene.frame_end`）。`anim_kit.scene_ctx()` 的返回值可以直接喂进来。

### 2. `shake` —— 相机抖动（T27）

给相机的 `location` / `rotation_euler` 三条通道的每条 F-Curve 挂一个 `NOISE` 修改器，
不重新烘焙任何关键帧，所以可以叠在已有运镜上面。

| 键 | 默认值 | 单位 | 适用场景 |
|---|---|---|---|
| `strength` | `0.03` | 弧度（旋转通道） | 约 1.7°，轻微手持；爆炸/落地可 0.06~0.1 |
| `loc_k` | `0.5` | 倍率 | 位置幅度 = `strength × loc_k`（米）。默认 0.015m，肉眼可见但不糊 |
| `scale` | `12` | 帧 | **噪波尺度：越小越抖**（8 = 高频抖，40 = 缓慢漂浮） |
| `depth` | `2` | 层 | 噪波的细节层数，0~10 |
| `phase` | 随机 | — | 每条曲线随机，避免三轴完全同步导致「整齐地画圈」 |
| `tracks` | `('location','rotation_euler')` | — | 只抖其中一个就传单个元素的 tuple |
| `frame_start` / `frame_end` | 整段 | 帧 | 给了就启用 limited range，只抖这一段（适合「只有落地那 8 帧抖」） |
| `blend_type` | 修改器默认 | — | 一般不用动 |

```python
ck.shake(sc, cam, ctx, {'strength': 0.02, 'scale': 8})
ck.shake(sc, cam, ctx, {'strength': 0.06, 'scale': 3,          # 爆炸：猛、短
                        'frame_start': 96, 'frame_end': 120, 'tracks': ('rotation_euler',)})
```

注意：`scale` 的单位是**帧**，所以它跟 fps 有关 —— 同样的 `scale` 在 60fps 下看
起来会比 24fps 抖得更细。

### 3. `orbit` —— 360° 环绕（T38）

新建空物体 `CAM_ORBIT_PIVOT` 当父级，相机挂成子物体放在局部 `(radius, 0, height)`，
空物体绕 Z 从 `rot_z` 转到 `rot_z + sweep`（只打首尾两帧、LINEAR 插值 → 匀速），
相机加 `TRACK_TO`（`TRACK_NEGATIVE_Z` / `UP_Y`）始终看向圆心。

| 键 | 默认值 | 单位 | 适用场景 |
|---|---|---|---|
| `rot_z` | `0` | 度 | 起始方位。想从角色左前方起转就设 180 |
| `sweep` | `360` | 度 | 只转半圈做展示可设 180 |
| `radius` | 相机当前水平距离 | 米 | **不传就沿用当前构图**，只加运动不改画面 |
| `height` | 相机当前高度 − 圆心高度 | 米 | 相对圆心的高度；正数俯拍、负数仰拍 |
| `aim_h` | `1.0` | 米 | 圆心离地高度（角色胸口）；`pivot` 给了就忽略 |
| `pivot` | 由 `target`/`ctx['base']` 推算 | `[x, y, z]` 米 | 圆心坐标，直接指定最可控 |
| `target` | `ctx['base']` | 物体名 / `[x,y,z]` | 占位符：指到角色就行 |
| `aim` | `True` | — | 是否加 `TRACK_TO`；只想要「绕圈横移」不要转向就设 `False` |
| `clear_keys` | `True` | — | **清掉相机原有的 location/rotation 曲线**，否则烘焙好的运镜会和绕圈叠在一起打架 |
| `pivot_name` | `'CAM_ORBIT_PIVOT'` | — | 想同时留多条环绕轨就换名字 |

```python
# 保持当前构图，原地转一圈
ck.orbit(sc, cam, ctx, {'sweep': 360})
# 指定圆心/半径/高度，半圈
ck.orbit(sc, cam, ctx, {'pivot': [0, 0, 0], 'radius': 7.0, 'height': 1.8,
                        'rot_z': 250, 'sweep': 180})
```

两个副作用要记住：
1. `clear_keys=True` 会**删掉**相机原有的机位 F-Curve（连同上一条 `shake` 挂的
   Noise 修改器一起没了）—— 所以 **`shake` 要放在 `orbit` 之后调用**；
2. 相机被换了父级，`cam.location` 从此是**相对圆心**的局部坐标，之后再写
   `cam.location = (0, -8, 2)` 是相对圆心的。

### 4. `cuts` —— 镜头切换（T33）

按 `shots` 生成 `cam_cut_1..n` 机位对象，并在时间线上插同名 marker，
`marker.camera` 直接绑到机位（Blender 5.x 的 `TimelineMarker` 有 `camera` 属性）。
**渲染时到了 marker 帧会自动换机位**，不需要动 `scene.camera`。

| 键 | 默认值 | 单位 | 适用场景 |
|---|---|---|---|
| `shots` | `[]`（空则跳过） | list | 每个 `{frame, az, dist, lens, height}` |
| `shots[].frame` | `1` | 帧 | marker 落点；渲染到这一帧切机位 |
| `shots[].az` | `0` | **度** | 方位角，MC 约定 `0 = +X`、`90 = +Y`（与 `anim_kit` 的 `az` 一致） |
| `shots[].dist` | `8` | 米 | 到瞄准点的水平距离 |
| `shots[].lens` | 继承主相机 | mm | 特写 85 / 中景 50 / 全景 35 |
| `shots[].height` | `0` | 米 | 相对瞄准点的高度（高低机位差） |
| `aim_h` | `1.0` | 米 | 瞄准点离地高度（胸口） |
| `height` | `0.0` | 米 | 所有机位的默认高度 |
| `target` | `ctx['base']` | 物体名 / `[x,y,z]` | 瞄准的地面点 |
| `prefix` | `'cam_cut_'` | — | 机位/标记名前缀 |
| `copy_data` | `True` | — | 复制主相机的数据块（DOF 等一起带过去） |
| `bind_scene_camera` | `False` | — | 顺便把 `scene.camera` 换成第一台（一般不用，marker 已够） |

```python
ck.cuts(sc, cam, ctx, {'target': [0, 0, 0], 'aim_h': 1.0, 'shots': [
    {'frame': 1,   'az': 250, 'dist': 8.0,  'lens': 50},                 # 全景
    {'frame': 60,  'az': 200, 'dist': 5.0,  'lens': 85, 'height': 0.6},   # 特写
    {'frame': 140, 'az': 300, 'dist': 12.0, 'lens': 35},                  # 过肩远景
]})
```

**幂等**：重跑会先删掉同名 marker 与旧机位对象，不会出现 `cam_cut_1.001` 一堆。
渲染多机位记得在输出里勾「按 marker 分段」或直接用 `ffmpeg_concat` 拼。

### 5. `sky_timelapse` —— 天空延时（T50）

World 的 Background 强度、Sky Texture 的 `sun_elevation`、以及太阳灯
（`type='SUN'`）的角度和强度，在给定帧上一起打关键帧。

| 键 | 默认值 | 单位 | 适用场景 |
|---|---|---|---|
| `hours` | `[]`（空则跳过） | list | `[{'frame': 1, 'hour': 6.5}, ...]`，也接受 `[[帧, 小时], ...]` |
| `hours[].hour` | — | 0~24 | 太阳高度角按正弦映射（见下） |
| `day_strength` | `1.0` | Background 强度 | 正午的天空亮度 |
| `night_strength` | `0.02` | Background 强度 | 夜里留一点环境光，别全黑；想要纯黑给 0 |
| `sun_energy` | 太阳灯当前能量 | W/m²（SUN） | 正午直射强度 |
| `sun_energy_night` | `sun_energy × 0.03` | W/m² | 夜里剩一点月光感 |
| `sun_azimuth` | 太阳灯当前 Z 旋转 | 弧度 | 不传就保持水平方向不变，只改高度 |
| `sun` | 场景第一盏 SUN 灯 | 灯物体 / 名字 | 指定用哪盏 |
| `linear` | `False` | — | 插值改 LINEAR，风格化的匀速变化 |

**小时 → 太阳高度角**（`sky_timelapse.sun_elevation_deg(hour)`）：

$$\text{高度角} = 90^\circ \times \sin\!\left(\frac{\pi\,(\text{hour} - 6)}{12}\right)$$

| 时刻 | 6:00 | 9:00 | 12:00 | 18:00 | 23:00 |
|---|---|---|---|---|---|
| 高度角 | 0° | +63.6° | +90° | 0° | −86.9° |

太阳灯的 `rotation_euler.x` 被设成 `90° + 高度角`（SUN 灯默认朝 −Z 打，这样
正午 `rot_x = 180°` 竖直向上照、日出 `90°` 水平擦地）。背景强度按
`day = max(0, sin(高度角))` 在 `night_strength`~`day_strength` 之间插值。

```python
ck.sky_timelapse(sc, cam, ctx, {'hours': [
    {'frame': 1,   'hour': 6.0},    # 日出
    {'frame': 60,  'hour': 9.0},
    {'frame': 120, 'hour': 12.0},   # 正午最亮
    {'frame': 180, 'hour': 18.0},   # 日落
    {'frame': 240, 'hour': 23.0},   # 入夜
], 'day_strength': 1.0, 'night_strength': 0.02, 'linear': True})
```

这个 op **不需要相机**：传 `cam=None` 会打一行提示（只操作 World / 太阳灯）然后照常执行。

### 6. 组合顺序建议

| 想做的效果 | 顺序 | 原因 |
|---|---|---|
| 环绕 + 手持抖动 | `orbit` → `shake` | `orbit` 会清掉相机旧曲线，先绕后抖 |
| 多机位 + 抖动 | `cuts` → `shake` | 抖的是主相机；要给机位也抖，对 `cam_cut_*` 再 call 一次 |
| 环绕 + 天空延时 | 任意顺序 | 一个动机位、一个动环境，互不干扰 |
| 环绕 + 换机位 | **二选一** | 两者都在定义「相机在哪」，同场景叠加只会互相覆盖 |

### 7. 版本兼容表（5.2.3 实测）

| 现象 | 真相 | 模块怎么处理 |
|---|---|---|
| `action.fcurves` 不存在 | 4.4 起 Action 拆成 `layers → strips → channelbags` | `iter_fcurves()` 两套都走；`_fcurve_containers()` 负责按容器 `remove()` |
| `sun.keyframe_insert('data.energy')` 抛 `path spans ID blocks` | 5.x 不允许跨 ID 块打关键帧 | 改成 `sun.data.keyframe_insert('energy')` |
| `TimelineMarker` 能不能存机位？ | 5.x 有 `camera` 属性，直接 `marker.camera = ob` | 有就绑，没有就只留同名 marker（`bound: False`） |
| 相机没动画曲线，Noise 修改器挂不上 | 修改器挂在 F-Curve 上，没有曲线就没有落点 | `_ensure_anim()` 先在首尾插静止关键帧把曲线建出来 |
| 相机被 `cuts` 复制出的数据块名冲突 | `.copy()` 会自动带 `.001` | 复制后显式 `camdata.name = name` |
| 太阳高度能不能为负？ | Sky Texture 的 `sun_elevation` 下限因 `sky_type` 而异 | 钳到 `[-10°, 89°]` 再写，失败就跳过并提示 |

## 四、坑清单（踩过的，别再踩）

1. **别硬编码引擎名**：`enum_items` 看不到 Cycles，`_NEXT` 后缀在 4.2~4.5 有、5.2 没有。
2. **`look='NONE'` 会报错**：5.x 的「无」是字符串 `'None'`。
3. **`render.file_format` 不存在**：格式在 `render.image_settings.file_format`。
4. **矢量模糊在 4.2+ 没有独立开关**：等价于运动模糊，靠 `motion_blur` 快门角控制。
5. **`keyframe_insert('data.energy')` 跨 ID 块会失败**：灯的能量打在 `light.data` 上。
6. **`ActionSlot` 没有 `.name`**（5.2 只有 `name_display` / `identifier`）：遍历动画时别读 `slot.name`。
7. **`orbit` 会清掉相机原有曲线**：把它当「重新定义机位」用，而不是「加一层」。抖动要后挂。
8. **`gpu=True` 改的是用户偏好**：会留下来，跑完记得 `{'gpu': False}` 或用完就重启 Blender。
9. **透明背景记得 RGBA**：`film_transparent=True` 时本模块会自动把
   `image_settings.color_mode` 设成 `RGBA`，手写脚本别漏。
10. **`cuts` 依赖 marker 才能切机位**：只设机位不打 marker，渲染出来还是主相机。
