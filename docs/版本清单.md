## 发布节奏的实际情况

- **npm 上的版本是断点的**：`0.4.2–0.4.5`、`0.4.9`、`0.5.0`、`0.5.1`、`0.5.5–0.5.9`
  都只打了 tag / 只提交，没发 npm；这些功能是在后面那个「整版」里一次性带出去的
  （`0.4.6`、`0.5.2`、`0.6.0`）。所以 npm 上看到的版本号会「跳号」，这是故意的：
  **只在功能补齐、回归测过之后才发**。
- 每次公开发布的常规动作：`git tag vX.Y.Z` → `git push --tags` → `npm stage publish`
  → **网页 Approve（2FA）** → 插件市场从 npm 重新拉包（无需另交材料）。
  详见下面「发布流程」一节。

## 发布流程（2026-11 起：npm 强制暂存 + 2FA）

npm 现在不再接受「直接 publish」：普通 token 报 403
（`Two-factor authentication or granular access token with bypass 2fa enabled is required`），
带 bypass 2FA 的 granular token 也只能进**暂存区**。所以流程是：

```bash
cd "E:\游戏与自媒体\AI自媒体工作区\04_工具脚本\dsh-blender-mc"
node scripts/smoke.mjs                        # 冒烟：13 个工具注册 + 语法
git tag vX.Y.Z && git push origin main --tags
npm pack                                      # 先打包，publish 直接指 tgz 省时间
npm stage publish ./dsh-blender-mc-X.Y.Z.tgz  # → staged with id <stage-id>
```

然后**必须人工在网页批准**（用暂存 token 跑 `npm stage approve <id>` 一律 404）：

1. https://www.npmjs.com/ → 左侧 **Staged Packages**
2. 找到该版本 → **Approve** → 输一次验证器 6 位码
3. 校验：`npm view dsh-blender-mc version dist-tags` 变成新版本、`latest` 指向它

### 凭证

- `~/.npmrc` 里是 `publish-verify` 这枚 granular token（2026-11-16 签发，**90 天有效，2027-02-14 到期**，
  只允许暂存发布）。到期前 3 天有定时提醒。
- 过期后重建：npmjs.com → Access Tokens → Generate New Token → Granular →
  勾 **Bypass 2FA**、Packages 选 Read and write → 把 `npm_…` 写进 `~/.npmrc`
  的 `//registry.npmjs.org/:_authToken=`。
- token 名称/签发日期记在这里，密钥本身不进仓库。
